# ZennoPoster MCP: Setup Guide for AI Assistants

:::warning Since 7.9.3, the built-in servers do not accept external assistants
The MCP servers that ProjectMaker starts by itself (the `6107`-`6113` port range, including `6107` and `6108`) serve only the built-in AI chat. An external client gets a `401` error, and the product log records `ingress refused`. The `BrowserMCP` (`6108`) and `ProjectMCP` (`6107`) entries added to your client earlier no longer work and can be removed.

Connect your assistant to your own copy of the server, started with your API key. It runs on the public servers' ports next to the built-in servers and does not interfere with the chat. How to start it is described below under "Preparation".
:::

---

## Preparation: API Key and Your Own Servers

You only do this once. You need two servers:

- **projectmaker** (Project control) → `http://localhost:6207`
- **instance-pm** (ProjectMaker browser control) → `http://localhost:6208`

### Step 1. Issue an API Key

1. Start ProjectMaker and open the project you need.
2. Open **Settings → API Keys → Add**.
3. Set a label, a tier and scopes. For read-only access to the project, tier `T0` with the default scopes is enough. To let the assistant edit the project and control the browser, add write scopes and raise the tier.
4. Click **Generate API Key** and copy the key right away: it is shown only once.

### Step 2. Download the Servers

On the [releases page](https://github.com/ZennoLab/zennoposter-mcp/releases), download the latest versions of two archives: `MCP.ProjectMaker-v…-win-x64.zip` and `MCP.Instance-v…-win-x64.zip`. Extract each one to its own folder, such as `C:\ZennoMCP\ProjectMaker` and `C:\ZennoMCP\Instance`. You do not need to install .NET.

### Step 3. Start the Servers with Your Key

Open the server folder, type `powershell` in the File Explorer address bar, and press Enter. Replace `zp_xxx` with your key.

```powershell title="Project, port 6207"
.\ZennoLab.AI.MCP.ProjectMaker.exe --ProjectMaker:ApiKey=zp_xxx
```

```powershell title="Browser, port 6208"
.\ZennoLab.AI.MCP.Instance.exe --Instance:ApiKey=zp_xxx
```

Keep both console windows open while you work with the assistant. To avoid entering the key every time, put it in the `ApiKey` field of the `appsettings.json` file next to the exe and start the server by double-clicking it.

Key permissions and the other servers (ZennoPoster tasks, ZennoDroid) are described in [Public API and MCP Servers](./Public_API_and_MCP.mdx).

## 1. GitHub Copilot

### Steps

1. Make sure ProjectMaker and your server copies are running.
2. Open your user profile folder: press `Win + R`, type `%USERPROFILE%`, press Enter.
3. Create a file named `.mcp.json` in that folder (e.g. `C:\Users\YourName\.mcp.json`).
4. Paste the following content:

```json
{
  "servers": {
    "projectmaker": {
      "type": "http",
      "url": "http://localhost:6207"
    },
    "instance-pm": {
      "type": "http",
      "url": "http://localhost:6208"
    }
  }
}
```

5. Restart Visual Studio (or reload the Copilot extension).
6. Copilot will now have access to both MCP servers in all your workspaces.

## 2. Claude Code (CLI)

### Steps

1. Make sure ProjectMaker and your server copies are running.
2. Open a terminal.
3. Run the following two commands:

```sh
claude mcp add projectmaker --transport http http://localhost:6207
claude mcp add instance-pm --transport http http://localhost:6208
```

4. Verify the servers are registered:

```sh
claude mcp list
```

5. The MCP servers are now available globally in all Claude Code sessions.

> To remove them later: `claude mcp remove projectmaker` and `claude mcp remove instance-pm`

## 3. OpenAI Codex CLI

### Steps

1. Make sure ProjectMaker and your server copies are running.
2. Open a terminal.
3. Run the following two commands:

```sh
codex mcp add projectmaker --url http://localhost:6207
codex mcp add instance-pm --url http://localhost:6208
```

4. Verify:

```sh
codex mcp list
```

## 4. LM Studio

### Steps

1. Make sure ProjectMaker and your server copies are running.
2. You need LM Studio 0.3.17 or newer and a model that supports tool use. Without it, the model cannot run commands.
3. In the right-hand sidebar of LM Studio, open the **Program** tab and click **Install → Edit mcp.json**.
4. Add the servers to the `mcpServers` section and save the file:

```json
{
  "mcpServers": {
    "projectmaker": { "url": "http://localhost:6207" },
    "instance-pm": { "url": "http://localhost:6208" }
  }
}
```

> Local models are weaker than cloud ones: they are good enough for reading and explaining a project, but complex edits work better with a cloud model.

## Troubleshooting

### The `claude` or `codex` command is not recognized

If the terminal shows an error like:

```
'claude' is not recognized as an internal or external command,
operable program or batch file.
```

or (in PowerShell):

```
claude : The term 'claude' is not recognized as the name of a cmdlet,
function, script file, or operable program.
```

(same applies to `codex`), it means the folder containing the CLI executable is **not in the `PATH` environment variable**, or the CLI is not installed, or the terminal was not restarted after installing.

> **Important:** the Claude Code website installer (native installer,
> `irm https://claude.ai/install.ps1 | iex`) does **not** add itself to `PATH`
> automatically. So "installed from the website but the command is not recognized"
> is the most common case. Step 2 below fixes it.

### Step 1. Find where the CLI is installed

The location of the executable depends on the install method.

**Claude Code:**

| Install method | Folder containing `claude` |
|---|---|
| Website (native): `irm https://claude.ai/install.ps1 \| iex` | `%USERPROFILE%\.local\bin` (e.g. `C:\Users\YourName\.local\bin`) |
| npm: `npm install -g @anthropic-ai/claude-code` | the npm folder, usually `%APPDATA%\npm` |

**OpenAI Codex CLI:**

| Install method | Folder containing `codex` |
|---|---|
| Website: `irm https://chatgpt.com/codex/install.ps1 \| iex` | the folder reported by the installer |
| npm: `npm install -g @openai/codex` | the npm folder, usually `%APPDATA%\npm` |
| Binary from [GitHub Releases](https://github.com/openai/codex/releases) | the folder where you extracted `codex.exe` |

You can find the exact npm folder with:

```powershell
npm config get prefix
```

Check whether the system sees the command at all (empty output means it is not in `PATH`):

```powershell
where.exe claude
where.exe codex
```

Check that the file exists (for the Claude website install):

```powershell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
```

If the file is not in any of these folders, the CLI is not installed. Install it using one of the methods from the tables above (npm requires [Node.js](https://nodejs.org/)).

### Step 2. Add the folder to the `PATH` variable

Use the path you found in Step 1 (e.g. `%USERPROFILE%\.local\bin` for the Claude website install, or `%APPDATA%\npm` for an npm install).

**Option A: via the Windows GUI**

1. Press `Win + R`, type `sysdm.cpl`, press Enter.
2. **Advanced** tab -> **Environment Variables** button.
3. Under **User variables**, select `Path` -> **Edit**.
4. Click **New** and paste the folder, for example:
   `C:\Users\YourName\.local\bin`
5. Click **OK** in all windows.

**Option B: via PowerShell (adds to the user `PATH` permanently)**

```powershell
# example for the Claude Code website install:
$p = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$p;$env:USERPROFILE\.local\bin", 'User')
```

> Replace the path with the one relevant to your case.
> Do not run the command several times in a row, or you will duplicate entries in `PATH`.

### Step 3. Restart the terminal and verify

`PATH` changes only take effect in **newly opened** terminal windows. Close and reopen PowerShell / CMD (or Visual Studio), then check:

```powershell
claude --version
codex --version
```

For Claude Code you can also run the built-in diagnostics (checks `PATH`, conflicting installs, etc.):

```powershell
claude doctor
```

If the versions are shown, the commands are recognized correctly and you can go back to the MCP setup steps above.

### Common causes if it still does not work

- **Terminal not restarted.** `PATH` changes only apply in newly opened windows.
- **Multiple installs at once** (npm + native) conflict. Keep one and remove the rest.
- **Only the VS Code extension is installed.** It does not add the `claude` command to the terminal. Install the standalone CLI from the website or via npm.

# ZennoDroid MCP: Setup Guide for AI Assistants

<DisclaimerNotice />

:::warning The built-in servers do not accept external assistants
The MCP servers that ProjectMaker ZennoDroid starts itself (ports `6117`, `6118` and the whole internal `6117`-`6123` range) serve only the built-in AI chat. An external client gets a `401` error, and the product log records `ingress refused`. The `ProjectMCP` (`6117`) and `AndroidMCP` (`6118`) entries added to your client earlier no longer work and can be removed.

Connect your assistant to your own copy of the server, started with your API key. It runs on the public servers' ports next to the built-in servers and does not interfere with the chat:

- **projectmaker-droid** (Project control) → `http://localhost:6217`
- **android-pm** (Android device inspection) → `http://localhost:6211`

See "Preparation" below for how to issue a key and start the servers.
:::

:::caution ZennoDroid ports differ from ZennoPoster by +10
This is intentional: ZennoPoster and ZennoDroid are often installed on the same machine and may be running at the same time. That is why the shared ports of the ZennoDroid AI stack are shifted by **+10** from their ZennoPoster counterparts — there is no conflict, and you can keep both products open and connect them to different sets of MCP servers. The exception is the device servers, `MCP.Android`: they exist only in ZennoDroid and take `6211` and `6212`.

If you copied the configuration from the [ZennoPoster MCP guide](/zennoposter/Hello/MCP_Setup) and specified `6207` / `6208`, your assistant will connect to **ZennoPoster**, not to ZennoDroid - ZennoDroid needs `6217` and `6211`.
:::

# Preparation: API Key and Your Own Servers {#preparation-api-key-and-your-own-servers}

You only do this once. ZennoDroid 2.6.1 or newer is required. You need two servers:

- **projectmaker-droid** (Project control) → `http://localhost:6217`
- **android-pm** (Android device inspection) → `http://localhost:6211`

## Step 1. Issue an API Key {#step-1-issue-an-api-key}

1. Start ProjectMaker ZennoDroid and open the project you need.
2. Open **Settings → API Keys → Add**.
3. Set a label, a tier and scopes. For read-only access to the project and the device, tier `T0` with the default scopes is enough. To let the assistant edit the project, add write scopes and raise the tier.
4. Click **Generate API Key** and copy the key right away: it is shown only once.

## Step 2. Download the Servers {#step-2-download-the-servers}

On the [releases page](https://github.com/ZennoLab/zennoposter-mcp/releases), download the latest versions of two archives: `MCP.ProjectMaker-v…-win-x64.zip` and `MCP.Android-v…-win-x64.zip`. Extract each one to its own folder. You do not need to install .NET.

## Step 3. Start the Servers with Your Key {#step-3-start-the-servers-with-your-key}

Open the server folder, type `powershell` in the File Explorer address bar, and press Enter. Replace `zp_xxx` with your key.

```powershell title="Project, port 6217"
.\ZennoLab.AI.MCP.ProjectMaker.exe --urls http://localhost:6217 `
  --ProjectMaker:BaseUrl=http://localhost:5309/api/v1 --ProjectMaker:ApiKey=zp_xxx
```

```powershell title="Device, port 6211"
.\ZennoLab.AI.MCP.Android.exe --Android:ApiKey=zp_xxx
```

Keep both console windows open while you work with the assistant. To avoid entering the key every time, put it in the `ApiKey` field of the `appsettings.json` file next to the exe and start the server by double-clicking it.

For ZennoDroid tasks (the runner) you need the `6220` (tasks and sessions) and `6212` (devices of running tasks) servers. Their commands and key permissions are described on the [Public API and MCP Servers](/zennoposter/Hello/public-api-mcp) page.

# 1. How ZennoDroid MCP differs from ZennoPoster MCP {#1-how-zennodroid-mcp-differs-from-zennoposter-mcp}

There are two differences, and the second one matters more than the first.

| | ZennoPoster | ZennoDroid |
|---|---|---|
| Project server | **projectmaker** `6207` | **projectmaker-droid** `6217` |
| Second server | **instance-pm** `6208` - controls the browser | **android-pm** `6211` - reads the state of the Android device |
| Recording mode | used — browser actions are written into cubes | **not used** — no ZennoDroid action requires recording |
| UI control from MCP | yes: clicks, text input, navigation | **no**: reading device state only |

**The key difference.** The `instance-pm` server in ZennoPoster can *act* - click, type, navigate. The `android-pm` server in ZennoDroid can only *look*: get the XML tree of the screen, the screen resolution, the list of apps, the device state.

Every action on the device in ZennoDroid is a **project cube**. The assistant adds them through the project server (`projectmaker-droid`), and they run when the project is executed (F5). So "tap the button in the app" in ZennoDroid means "add a cube to the project that will tap this button", not "tap it right now".

A practical consequence: an element that is not on the screen right now is not an obstacle. The cube is built from the element's name/text/attribute and fires while the project runs.

> The exact list of tools each server provides, and their parameters, is something the assistant receives from the MCP servers itself, on connection. Just ask it — it will list what is available in your build.

# 2. GitHub Copilot {#2-github-copilot}

## Steps

1. Make sure ProjectMaker ZennoDroid and your server copies are running.
2. Open your user profile folder: press `Win + R`, type `%USERPROFILE%`, press Enter.
3. Create a file named `.mcp.json` in that folder
   (e.g. `C:\Users\YourName\.mcp.json`)
4. Paste the following content:

```json
{
  "servers": {
    "projectmaker-droid": {
      "type": "http",
      "url": "http://localhost:6217"
    },
    "android-pm": {
      "type": "http",
      "url": "http://localhost:6211"
    }
  }
}
```

5. Restart Visual Studio (or reload the Copilot extension).
6. Copilot now has access to both MCP servers in all workspaces.

:::tip If you work with both ZennoPoster and ZennoDroid
You can keep all four servers in a single `.mcp.json` — the names must differ, the ports already do:

```json
{
  "servers": {
    "projectmaker-droid": { "type": "http", "url": "http://localhost:6217" },
    "android-pm":         { "type": "http", "url": "http://localhost:6211" },
    "projectmaker":       { "type": "http", "url": "http://localhost:6207" },
    "instance-pm":        { "type": "http", "url": "http://localhost:6208" }
  }
}
```

Keep in mind: the assistant will see the tools of both products at once and may reach for the wrong server. If that gets in the way, state which product you mean in your request, or keep only the set you need connected.
:::

# 3. Claude Code (CLI) {#3-claude-code-cli}

## Steps

1. Make sure ProjectMaker ZennoDroid and your server copies are running.
2. Open a terminal.
3. Run the following commands:

```sh
claude mcp add projectmaker-droid --transport http http://localhost:6217
claude mcp add android-pm --transport http http://localhost:6211
```

4. Verify the servers are registered:

```sh
claude mcp list
```

5. The MCP servers are now available globally in all Claude Code sessions.

> To remove them later:
>
> `claude mcp remove projectmaker-droid`
>
> `claude mcp remove android-pm`

# Troubleshooting {#troubleshooting}

## The assistant connected, but it sees the ZennoPoster project instead of ZennoDroid

The most common mistake when coming from the ZennoPoster guide: the configuration specifies ports `6207` / `6208`. Those are the ZennoPoster public servers. ZennoDroid needs **`6217` and `6211`**.

To check who is listening on which port:

```powershell
netstat -ano | findstr ":6207 :6208 :6211 :6212 :6217 :6220"
```

To map a PID to a process:

```powershell
Get-Process -Id <PID>
```

## The assistant gets a `401` error {#the-assistant-gets-a-401-error}

The client is connected to a built-in server (`6117`-`6123`): it serves only the built-in AI chat and does not accept external clients. Start your own copy of the server and point the client to its port: `6217`, `6211`, `6212` or `6220`.

## Device-reading tools return an error or an empty result

- **The device is not running.** Reading the screen, the list of apps and the resolution all require the device to be up. Ask the assistant to bring the device up first — that tool is idempotent and will not do anything extra.
- **No device is selected.** For a real phone it must be connected and visible to ZennoDroid (see [connecting a device](../Enterprise/Connection)).

## The `claude` or `codex` command is not recognized

If the terminal shows an error like:

```
'claude' is not recognized as an internal or external command,
operable program or batch file.
```

or (in PowerShell):

```
claude : The term 'claude' is not recognized as the name of a cmdlet,
function, script file, or operable program.
```

(the same applies to `codex`), it means the folder containing the CLI executable is **not in the `PATH` environment variable**, or the CLI is not installed, or the terminal was not restarted after installing.

> ⚠️ **Important:** the Claude Code website installer (native installer,
> `irm https://claude.ai/install.ps1 | iex`) does **not** add itself to `PATH`
> automatically. So "installed from the website but the command is not recognized"
> is the most common case. Step 2 below fixes it.

### Step 1. Find where the CLI is installed

The location of the executable depends on the install method.

**Claude Code:**

| Install method | Folder containing `claude` |
|---|---|
| Website (native): `irm https://claude.ai/install.ps1 \| iex` | `%USERPROFILE%\.local\bin` (e.g. `C:\Users\YourName\.local\bin`) |
| npm: `npm install -g @anthropic-ai/claude-code` | the npm folder, usually `%APPDATA%\npm` |

**OpenAI Codex CLI:**

| Install method | Folder containing `codex` |
|---|---|
| Website: `irm https://chatgpt.com/codex/install.ps1 \| iex` | the folder reported by the installer |
| npm: `npm install -g @openai/codex` | the npm folder, usually `%APPDATA%\npm` |
| Binary from [GitHub Releases](https://github.com/openai/codex/releases) | the folder where you extracted `codex.exe` |

You can find the exact npm folder with:

```powershell
npm config get prefix
```

To check whether the system sees the command at all (empty output means it is not in `PATH`):

```powershell
where.exe claude
where.exe codex
```

To check that the file exists (for the Claude website install):

```powershell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
```

If the file is in none of those folders, the CLI is not installed. Install it using one of the methods from the tables above (npm requires [Node.js](https://nodejs.org/)).

### Step 2. Add the folder you found to `PATH`

Substitute the path from Step 1 (for example `%USERPROFILE%\.local\bin` for the Claude website install,
or `%APPDATA%\npm` for an npm install).

**Option A: through the Windows GUI**

1. Press `Win + R`, type `sysdm.cpl`, press Enter.
2. **"Advanced"** tab → **"Environment Variables"** button.
3. Under **"User variables"** select the `Path` variable → **"Edit"**.
4. Click **"New"** and paste the required path, for example:
   `C:\Users\YourName\.local\bin`
5. Click **OK** in all windows.

**Option B: through PowerShell (adds to the user `PATH` permanently)**

```powershell
# example for the Claude Code website install:
$p = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$p;$env:USERPROFILE\.local\bin", 'User')
```

> ⚠️ Replace the path with the one that applies to your case.
> Do not run the command several times in a row, or you will duplicate entries in `PATH`.

### Step 3. Restart the terminal and check

`PATH` changes only take effect in **new** terminal windows. Close and reopen PowerShell / CMD (or Visual Studio), then check:

```powershell
claude --version
codex --version
```

For Claude Code you can also run the built-in diagnostics (it checks `PATH`, conflicting installs, and so on):

```powershell
claude doctor
```

If the versions are displayed, the commands are recognized correctly and you can go back to the MCP setup steps above.

### Common causes if that did not help

- **The terminal was not restarted.** `PATH` changes only apply in newly opened windows.
- **Several installs at once** (npm + native) conflict. Keep one and remove the rest.
- **Only the VS Code extension is installed.** It does not add the `claude` command to the terminal. Install the standalone CLI from the website or via npm.

# Example requests {#example-requests}

## Device inspection

```
Bring the device up and show information about it.
```

```
Tell me the device's screen resolution.
```

```
Get the element structure of the current screen
and find the input field in it.
```

```
Show the list of installed applications
and find the exact package name for Chrome.
```

---

## Building the project

```
Show the structure of the current project,
list all actions with their IDs and types.
```

```
Tell me whether my project targets the emulator or a real phone,
and which action categories are available.
```

```
Build a chain: select a random device,
start it and open https://example.com.
```

```
Add a check: if the text "Success" appeared on screen —
go down the success branch, otherwise down the error branch.
```

```
Show the current project execution logs
and tell me whether there are any errors.
```

---

## Combining device reads with project building

```
Read the screen structure, find the phone input field,
and add a cube to the project that types {-Variable.phone-} into it.
```

```
Determine the package name of WhatsApp from the installed list,
then add a check to the project for whether it is installed.
```

```
Read the real screen resolution
and add a bottom-to-top swipe through the centre of the screen.
```

# App API
<DisclaimerNotice />
## Description

`IDroidAppAPI` is designed to manage applications on an Android device in ZennoDroid. Provides methods for working with app data, accounts, notifications, cookies, and app state.

Most methods accept a `packageName` parameter — the app's package name. Use the [**Installed Apps**](../Tools/Installed_App) tool to find the right name.

This follows the same logic as the **App Actions** block for the [**Lite/Pro**](../Android/pro-lite/App) and [**Enterprise**](../Android/Enterprise/App) versions.

### DeleteCookie

- **`string DeleteCookie(string packageName, string host = null, string name = null, bool persistentOnly = false, bool secureOnly = false, bool httpOnly = false)`**  
    Deletes cookies from the app's Chromium store. The filters are the same as in `GetCookie` and are applied on the device.
    
    **Parameters:**
    - `packageName` — package name;
    - `host` — domain filter: deletes cookies of this domain and its subdomains, several domains are separated by commas. An empty value means any domain;
    - `name` — cookie name filter (exact match), several names are separated by commas. An empty value means any name;
    - `persistentOnly` — delete only persistent cookies, leaving session ones untouched;
    - `secureOnly` — delete only cookies with the `Secure` flag;
    - `httpOnly` — delete only cookies with the `HttpOnly` flag.
    
    **Returns:**  
    A JSON report of the deletion: how many cookies were scanned and deleted for each database.

#### Example  
```csharp
var app = instance.DroidInstance.App;

var packageName = "com.android.chrome"; // App name

// Delete a single cookie of example.com and its subdomains
var report = app.DeleteCookie(packageName, "example.com", "sid");
project.Json.FromString(report);

// Wipe the app's cookie store completely
app.DeleteCookie(packageName);
```

:::warning Important notes
- A call **with no filters deletes every cookie** of the app.
- **Root** is required: the app is force-stopped during the deletion, and its data directory is written to.
- If the app has never been launched, its cookie store does not exist yet and the method returns an empty string.
:::

### GetCookie

- **`string GetCookie(string packageName)`**  
    Gets the app's cookies.
    
    **Parameters:**
    - `packageName` — package name.
    
    **Returns:**  
    A string with cookies.

- **`string GetCookie(string packageName, string host, string name = null, bool persistentOnly = false, bool secureOnly = false, bool httpOnly = false)`**  
    Gets the app's cookies with filtering. The filters are applied on the device before the values are decrypted, which makes this overload convenient for large stores.
    
    **Parameters:**
    - `packageName` — package name;
    - `host` — domain filter: keeps cookies of this domain and its subdomains, several domains are separated by commas. An empty value means any domain;
    - `name` — cookie name filter (exact match), several names are separated by commas. An empty value means any name;
    - `persistentOnly` — exclude session cookies;
    - `secureOnly` — keep only cookies with the `Secure` flag;
    - `httpOnly` — keep only cookies with the `HttpOnly` flag.
    
    **Returns:**  
    A string with cookies in the same format as `GetCookie(packageName)`.

#### Example  
```csharp
var app = instance.DroidInstance.App;

var packageName = "com.android.chrome"; // App name
var cookies = app.GetCookie(packageName); // Get app cookies

// Only persistent Secure cookies of example.com and its subdomains
var filtered = app.GetCookie(packageName, "example.com", null, true, true);
```

### ImportCookie

- **`string ImportCookie(string packageName, string cookies, bool replaceAll = false)`**  
    Imports cookies into the app's Chromium store. The values are encrypted on the device with the same scheme the app itself uses.
    
    **Parameters:**
    - `packageName` — package name;
    - `cookies` — cookies as a JSON array in the ZennoLab format (the same one `GetCookie` returns);
    - `replaceAll` — `true` clears the store before the import, `false` adds the cookies and updates the existing ones.
    
    **Returns:**  
    A JSON report of the import: how many cookies were inserted, replaced, skipped, and failed for each database.

#### Example  
```csharp
var app = instance.DroidInstance.App;

var packageName = "com.android.chrome"; // App name

var cookies = @"[{
  ""domain"": "".example.com"",
  ""name"": ""sid"",
  ""value"": ""abc123"",
  ""path"": ""/"",
  ""expirationDate"": 1790000000,
  ""httpOnly"": true,
  ""secure"": true,
  ""sameSite"": ""Lax"",
  ""is_persistent"": true
}]"; // Cookies in the ZennoLab format

var report = app.ImportCookie(packageName, cookies); // Add the cookies to the app's store
project.Json.FromString(report);
```

:::warning Important notes
- **Root** is required: the app is force-stopped during the import, and the store is written on its behalf.
- The app has to be launched at least once, otherwise its cookie store does not exist yet and the method returns an error.
:::

### InjectScript

- **`void InjectScript(string packageName, string script)`**  
    Injects a JavaScript script into an app that runs before page load.
    
    **Parameters:**
    - `packageName` — package name;
    - `script` — script code.

#### Example  
```csharp
var app = "com.android.chrome";
var script = project.Variables["script"].Value;

instance.DroidInstance.App.Close(app); // Close the app

var lspHelper = new LSPosedHelper(instance.DroidInstance);
lspHelper.SetPackages(app); // Set the app in the ZennoDroid module spoofing list
lspHelper.EnableModule(); // Enable the ZennoDroid module

instance.DroidInstance.Settings.SetLSPosedSettings("{ \"UseInjectScript\":true }"); // Enable JavaScript injection before page load
instance.DroidInstance.App.InjectScript(app, script); // Set the script to execute before page load

instance.DroidInstance.App.Open(app); // Open the app
```
The project variable *script* contains the code to execute.
```javascript
(() => {
  const ID = "hello-world-date-banner";
  const existing = document.getElementById(ID);
  const text = `Hello world — ${new Date().toLocaleString()}`;

  if (existing) {
    existing.textContent = text; // already added: just update
    return;
  }

  const el = document.createElement("div");
  el.id = ID;
  el.textContent = text;
  el.style.cssText =
    "padding:8px 12px;background:#fffbcc;color:#111;" +
    "font:14px/1.4 system-ui;border-bottom:1px solid #e6d98c;";
  (document.body || document.documentElement).prepend(el);
})();
```

### SetVideoForFakeCamera

:::info **Available starting from ZennoDroid 2.6.1.0.**
:::

- **`void SetVideoForFakeCamera(string packageName, string videoSource)`**  
    Feeds a video file to the app's camera instead of the real sensor, so the app receives the video frames as if they came from the device camera. The video plays in a loop, without sound, and every frame lane stays virtual. Use the overload with playback options if the app also needs to save photos.
    
    **Parameters:**
    - `packageName` — package name of the target app;
    - `videoSource` — path to the video. Either a local path on the PC (e.g. `c:\source.mp4`), which is pushed to the device, or a path that already exists on the device (starts with `/`, e.g. `/sdcard/Download/source.mp4`), which is copied without a PC transfer. An empty string disables the substitution and returns the real camera.
    
    **Description:**  
    Any container MediaCodec can decode works (`.mp4`, `.mkv`, `.webm`, `.3gp`, `.m4v`, `.mov`), and the resolution of the video need not match what the app requests.
    
    The video is cached on the device by its content hash, so pushing the same file again — or reusing it for another app — does not transfer it a second time.
    
    The video can be replaced while the camera is running: a subsequent call switches playback without restarting the app or its camera session.

- **`void SetVideoForFakeCamera(string packageName, string videoSource, bool loop, bool mute, bool photo)`**  
    The same, with explicit playback options.
    
    **Parameters:**
    - `packageName` — package name of the target app;
    - `videoSource` — path to the video on the PC or on the device, or an empty string to disable the substitution;
    - `loop` — restart the video when it ends. When `false`, the last frame remains on screen;
    - `mute` — suppress the audio track of the video. Pass `false` to play the sound;
    - `photo` — let a camera app finish saving a photo.

#### Example  
```csharp
var app = instance.DroidInstance.App;

var packageName = "com.android.chrome"; // App name

// A video from the PC: pushed to the device, played in a loop and without sound
app.SetVideoForFakeCamera(packageName, @"c:\source.mp4");

// A video that is already on the device: with sound, without looping, photos allowed
app.SetVideoForFakeCamera(packageName, "/sdcard/Download/source.mp4", false, false, true);

// Return the real camera
app.SetVideoForFakeCamera(packageName, "");
```

The substitution starts working only once the **ZennoVCam** module is enabled in LSPosed and the target app is on its list. That is done through the [**LSPosed API**](./LSPosed) — here it is turned on for the default Camera app:
```csharp
var packageName = "com.android.camera2"; // The default Camera app

instance.DroidInstance.App.Close(packageName); // Close the app

var lspHelper = new LSPosedHelper(instance.DroidInstance);
lspHelper.ModuleName = "com.zennolab.zennovcam"; // Work with the ZennoVCam module
lspHelper.SetPackages(packageName); // Put the app on the scope list of the ZennoVCam module
lspHelper.EnableModule(); // Enable the ZennoVCam module

instance.DroidInstance.App.SetVideoForFakeCamera(packageName, @"c:\source.mp4"); // Feed the video to the camera

instance.DroidInstance.App.Open(packageName); // Open the app
```
The scope list is set **before** the module is enabled: with an empty list `EnableModule` fails with *Add any package!*. The module itself does not have to be installed by hand — `SetPackages` delivers it to the device if it is not there yet.

:::warning Important notes
- `photo` is off by default because it is a trade rather than a strict improvement: to get the save through, the module hands the small helper frame lanes (metering, thumbnails) back to the real camera. Leave it `false` for a scanner or KYC app that reads frames through one of those lanes, since it would otherwise receive the real camera image.
:::

# BlueStacks5 API
<DisclaimerNotice />
## Description

A set of interfaces for managing the **BlueStacks 5** emulator in ZennoDroid Enterprise.

| Interface | Description |
|---|---|
| `IBlueStacks5API` | Starting, stopping, and connecting to the emulator |
| `IBlueStacks5SettingsAPI` | System parameters: geolocation, IMEI |
| `IBlueStacks5RootAPI` | Managing root access and Magisk |
| `IBlueStacks5ManagerAPI` | Creating and deleting instances via the manager |

_______________________________________________
## IBlueStacks5API

Managing the startup, shutdown, and connection of the BlueStacks 5 emulator.

### AddressPort

- **`string AddressPort { get; }`**  
    Connection address and port of the emulator.
    
    **Returns:**  
    A string in `IP:Port` format (e.g. `127.0.0.1:5555`).

---

### IsBootCompleted

- **`bool IsBootCompleted { get; }`**  
    Checks whether Android has finished booting inside the emulator.
    
    **Returns:**  
    `true` if the system is fully loaded and ready to use.

---

### IsRunning

- **`bool IsRunning { get; }`**  
    Checks whether the emulator is running.
    
    **Returns:**  
    `true` if the emulator is running; otherwise `false`.

---

### Connect

- **`void Connect()`**  
    Connects to the emulator (typically via ADB).

---

### Disconnect

- **`void Disconnect()`**  
    Disconnects from the emulator.

---

### Start

- **`void Start()`**  
    Starts the BlueStacks emulator.

#### Example
```csharp
new BlueStacks5("Rvc64_1", "nxt").Start();
```

---

### Stop

- **`void Stop()`**  
    Stops the emulator.

---

### WaitForBoot

- **`bool WaitForBoot(int timeout)`**  
    Waits until Android has finished booting: the process is running, ADB is connected, and `IsBootCompleted` returns `true`.
    
    **Parameters:**
    - `timeout` — how long to wait, in seconds (`0` checks once).
    
    **Returns:**  
    `true` if the emulator booted; `false` if the time ran out.
    
    **Description:**  
    Call it after every `Start()`: that only asks the player to come up and returns immediately, without waiting for the boot.

#### Example
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Start();
if (!bs.WaitForBoot(120)) throw new Exception("The emulator did not boot");
```

---

### WaitForConnect

- **`bool WaitForConnect(int timeout)`**  
    Connects over ADB and waits until the connection actually answers a command.
    
    **Parameters:**
    - `timeout` — how long to keep trying, in seconds (`0` checks once).
    
    **Returns:**  
    `true` if the connection answers; `false` if the time ran out.
    
    **Description:**  
    `Connect()` succeeds before the emulator is ready to answer, and the first command after it comes back empty or as an error — this method spends that command itself.

---

### WaitForStop

- **`bool WaitForStop(int timeout)`**  
    Waits until the emulator process is gone.
    
    **Parameters:**
    - `timeout` — how long to wait, in seconds (`0` checks once).
    
    **Returns:**  
    `true` if the process is gone; `false` if the time ran out.
    
    **Description:**  
    Call it after every `Stop()`: that only asks the player to shut down, and the instance disks stay locked until the process is actually gone — which is what operations on a stopped instance, `Unlock()` and `Lock()` among them, wait for.

:::note Important Notes
- After `Start()`, wait for the boot with `WaitForBoot()` (or check `IsBootCompleted`) before performing any actions.
- After `Stop()`, wait for `WaitForStop()`: the instance disks stay locked while the process is alive.
- `Connect()` should be called after the emulator has started, and the connection checked with `WaitForConnect()`.
- In some scenarios, reconnection may be required when ADB fails.
:::

## IBlueStacks5SettingsAPI

Modifying system parameters of the BlueStacks 5 emulator.

### SetGeo

- **`void SetGeo(double longitude, double latitude)`**  
    Sets the device's geolocation.
    
    **Parameters:**
    - `longitude` — longitude (e.g. `37.6173`);
    - `latitude` — latitude (e.g. `55.7558`).
    
    **Description:**  
    Allows emulating the device's location at a specified point on the map.

#### Example
```csharp
new BlueStacks5Settings("Rvc64_1", "nxt").SetGeo(-73.572604, 40.651980);
```

---

### SetIMEI

- **`void SetIMEI(string value)`**  
    Sets the device IMEI.
    
    **Parameters:**
    - `value` — IMEI string value.
    
    **Description:**  
    Used to spoof the device identifier.

:::warning Important Notes
- Invalid IMEI values may cause errors in applications or be detected as invalid.
- After changing parameters, it is recommended to restart the emulator and reconnect.
- Geolocation may additionally be cached by applications — sometimes a restart is required.
:::

## IBlueStacks5RootAPI

Managing root access, Magisk, and patches in the BlueStacks 5 emulator.

### IsRooted

- **`bool IsRooted { get; }`**  
    Checks whether root answers on the instance right now.
    
    **Returns:**  
    `true` if root answers; otherwise `false`.
    
    **Description:**  
    It is asked the same way the root steps ask it, so it holds for whichever `su` the instance ended up with. For an instance that is stopped, still booting, or simply not rooted it returns `false` and never throws.

---

### EnableZygisk

- **`void EnableZygisk()`**  
    Enables Zygisk — a Magisk module for injecting into processes via Zygote. Supported on Android 9 (Pie) and above.
    
    **Description:**  
    Allows using advanced modules and hooks (e.g. for bypassing root detection).

---

- **`void EnableZygisk(string modulePath)`**  
    Enables Zygisk using the given provider module — for the Magisk builds whose own Zygisk cannot be used on an emulator. The module is installed first, then Zygisk is configured to defer to it.
    
    **Parameters:**
    - `modulePath` — path to the Zygisk provider module `.zip` file (NeoZygisk).
    
    **Description:**  
    Takes effect after the emulator is restarted. On Android 7 the call is refused rather than quietly doing nothing: that image has no Zygisk at all, although root does work on it.

---

### FlashMagisk

- **`void FlashMagisk()`**  
    Flashes (installs) Magisk into the system.
    
    **Description:**  
    Applies Magisk at the system level after installation.

---

### InstallMagisk

- **`void InstallMagisk(string path)`**  
    Installs Magisk from the specified file.
    
    **Parameters:**
    - `path` — path to the Magisk file (`.apk`).

---

### InstallMagiskOffline

- **`void InstallMagiskOffline(string magiskApk)`**  
    Lays Magisk out on the system image of a stopped, unlocked instance, without starting anything.
    
    **Parameters:**
    - `magiskApk` — path to the Magisk `.apk` to take the binaries from.
    
    **Description:**  
    Replaces `Patch()` + `InstallMagisk()` + `FlashMagisk()` together with the restarts they need: root comes up on the next boot, from the init trigger this method writes. The instance has to be stopped (a running player holds its images) and has to have been through `Unlock(bool)` — what this writes into is the clone of the system disk that unlock puts in place. The apk is read for its binaries only; the manager app is still installed with `InstallMagisk()`, on the booted instance.

---

### InstallModule

- **`void InstallModule(string path)`**  
    Installs a Magisk module from the specified zip file (LSPosed, Vector, and others).
    
    **Parameters:**
    - `path` — path to the module `.zip` file.
    
    **Description:**  
    Modules are applied when the emulator is restarted.

---

### InstallModuleOffline

- **`bool InstallModuleOffline(string modulePath)`**  
    Puts a Zygisk provider module into the data image of a stopped instance, laid out the way the installer of the module would have laid it out.
    
    **Parameters:**
    - `modulePath` — path to the Zygisk provider module `.zip` file.
    
    **Returns:**  
    `true` if the module was written; `false` if `/data` has never been initialised.
    
    **Description:**  
    The module is live on the next boot instead of the one after it. `false` is not a failure: it means `/data` is not there to write into yet. Android lays it out on the very first boot of an instance and would take anything written before that along with it, so the answer is to boot once and call the method again — which is what `SetupRootOffline()` does. On Android 7 it throws: there is no Zygisk there to provide for.

---

### Lock

- **`void Lock()`**  
    Locks root access in the emulator. Restores the system partition to a non-root state.
    
    **Description:**  
    Disables root, making the system more "clean" (e.g. for bypassing application checks).

---

### Patch

- **`void Patch()`**  
    Applies a patch to prepare the system for root.
    
    **Description:**  
    Modifies emulator system components to support root access.

---

### Unlock

- **`void Unlock()`**  
    Unlocks root access.
    
    **Description:**  
    Puts the system partition in write mode. Allows making changes to gain root access.

#### Example
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").Unlock();
```

---

- **`void Unlock(bool patchImage)`**  
    The same unlock, with a say over whether the system image is also patched.
    
    **Parameters:**
    - `patchImage` — `true` is what `Unlock()` does; `false` skips the patch.
    
    **Description:**  
    That patch serves the online root and nothing else — it is how root is got on a **running** instance so that files can be copied in — so an offline install passes `false` and leaves the image stock.

---

### WaitForRoot

- **`bool WaitForRoot(int timeout)`**  
    Waits until root answers.
    
    **Parameters:**
    - `timeout` — how long to wait, in seconds (`0` checks once).
    
    **Returns:**  
    `true` if root answers; `false` if the time ran out.
    
    **Description:**  
    Root is not there the moment Android reports the boot as complete — the `su` daemon comes up on its own a few seconds later — so a single `IsRooted` right after a restart says nothing.

:::warning Important Notes
- Root operations may affect emulator stability or break application functionality.
- After changes, restarting the emulator and verifying root status is recommended.
- Used together with [`IFridaDeviceAPI`](./Frida), [`IDroidAppAPI`](./App), and `RootShell` ([`IDroidInputAPI`](./Input#rootshell)).
:::

## IBlueStacks5ManagerAPI

Managing BlueStacks 5 instances via the manager: creating, deleting, starting/stopping the service.

**Constructor:** `BlueStacks5Manager(string oem)`

- `oem` — string identifying the BlueStacks version:
    - `"nxt"` — standard version
    - `"nxt_cn"` — China version
    - `"msi5"` — MSI version (MSI App Player 5)

### Create

- **`string Create(string imageName, int cpus, int ram, string graphicEngine, string graphicRenderer, string deviceProfile, string abiList)`**  
    Creates a new emulator instance with the specified parameters.
    
    **Parameters:**
    - `imageName` — base emulator image:
        - `"Nougat32"` — Android 7.1 (x86)
        - `"Nougat64"` — Android 7.1 (x64)
        - `"Pie64"` — Android 9.0 (x64)
        - `"Rvc64"` — Android 11.0 (x64)
        - `"Tiramisu64"` — Android 13.0 (x64)
    - `cpus` — number of allocated CPUs;
    - `ram` — amount of RAM (MB);
    - `graphicEngine` — graphics engine (Android 7 only):
        - `"aga"` — Compatibility
        - `"pga"` — Performance
    - `graphicRenderer` — render type:
        - `"gl"` — OpenGL
        - `"dx"` — DirectX
        - `"vlcn"` — Vulkan
    - `deviceProfile` — device profile:
        - `"rogt"` — Asus ROG 2
        - `"ptxg"` — Google Pixel 2XL
        - `"optp"` — OnePlus 10 Pro
        - `"opet"` — OnePlus 8T
        - `"anfg"` — Samsung Galaxy A90 5G
        - `"smtn"` — Samsung Galaxy S10
        - `"stfg"` — Samsung Galaxy S10 5G
        - `"stul"` — Samsung Galaxy S20 Ultra
        - `"stwp"` — Samsung Galaxy S20+
        - `"stou"` — Samsung Galaxy S21 Ultra
        - `"sstt"` — Samsung Galaxy S22
        - `"sttu"` — Samsung Galaxy S22 Ultra
        - `"xitp"` — Xiaomi 11T Pro
    - `abiList` — list of supported ABIs (e.g. `"x86,x64,arm,arm64"`).
    
    **Returns:**  
    The name of the created instance.

#### Example
```csharp
var name = new BlueStacks5Manager("nxt").Create("Rvc64", 
	cpus:2, 
	ram:2048,
	graphicEngine:"aga",
	graphicRenderer:"dx",
	deviceProfile:"xitp", 
	abiList:"x86,x64,arm,arm64");
```

---

### DeleteByName

- **`void DeleteByName(string name)`**  
    Deletes an emulator instance by name.
    
    **Parameters:**
    - `name` — instance name.

---

### Exists

- **`bool Exists(string name)`**  
    Checks whether an instance with the given system name exists.
    
    **Parameters:**
    - `name` — system name of the instance.
    
    **Returns:**  
    `true` if such an instance is registered.
    
    **Description:**

- **`string[] GetListNames()`**  
    System names of everything this OEM has registered.
    
    **Returns:**  
    An array of system names.
    
    **Description:**  
    Base images are among them — those are what new instances are cloned from, and they are listed exactly as an instance would be.

---

### GetListTitles

- **`string[] GetListTitles()`**  
    Display titles of the same list.
    
    **Returns:**  
    An array of titles, in the same order as `GetListNames()`.

---

### NameToTitleConverter

- **`string NameToTitleConverter(string name)`**  
    Converts an internal system name back to the display title shown in the interface.
    
    **Parameters:**
    - `name` — system name of the instance.
    
    **Returns:**  
    Display title of the instance.

---

### SetupRoot

- **`void SetupRoot(string title, string magiskApk, string zygiskModule, int timeout)`**  
    Runs the whole root pipeline on the instance and leaves it running, rooted, with Zygisk live.
    
    **Parameters:**
    - `title` — display title as shown in the BlueStacks interface (a system name is accepted too);
    - `magiskApk` — path to the Magisk `.apk`. Empty takes `MagiskSource.DefaultApk`, the copy that ships with ZennoDroid;
    - `zygiskModule` — path to a Zygisk provider module `.zip` (NeoZygisk), which is what the Magisk builds whose own Zygisk cannot work on an emulator need; `MagiskSource.DefaultZygiskModule` is the copy that ships with ZennoDroid. Empty turns on Magisk's own Zygisk instead;
    - `timeout` — how long each wait in the sequence may take, in seconds.
    
    **Description:**  
    Every step of the pipeline is a method of this API and every wait is one too, so the same thing can be done step by step. With `name = TitleToNameConverter(title)`, `bs = new BlueStacks5(name, oem)` and `root = new BlueStacks5Root(name, oem)`, this is exactly what runs:

```csharp
bs.Stop();  bs.WaitForStop(timeout);   // Unlock needs the disks free
root.Unlock();
bs.Start(); bs.WaitForBoot(timeout);   // Patch needs Android up
root.Patch();
root.InstallMagisk(magiskApk);
root.FlashMagisk();
bs.Stop();  bs.WaitForStop(timeout);   // the Magisk daemon only starts on boot
bs.Start(); bs.WaitForBoot(timeout);
if (!root.WaitForRoot(timeout))        // whether Patch has to be repeated — see below
    root.Patch();
root.EnableZygisk(zygiskModule);
bs.Stop();  bs.WaitForStop(timeout);   // a Zygisk loader is only picked up by a zygote
bs.Start(); bs.WaitForBoot(timeout);   // that starts after the daemon
```

Root is bind mounts and those do not survive a boot, so with some Magisk builds the patch has to be made again after the restart. But the system-mode flash of upstream Magisk installs a boot trigger that remakes it, and patching on top of that only fights with it — so which one it is is asked (`WaitForRoot()`) rather than assumed.

On Android 7 the Zygisk step is skipped and everything before it still runs: that image has no Zygisk, and root on it is worth having on its own.

Throws if a step fails or a wait runs out of time; the message names the stage it stopped at.

#### Example
```csharp
var mgr = new BlueStacks5Manager("nxt");
mgr.SetupRoot("BlueStacks Rvc64", "", "", 120);
```

---

### SetupRootOffline

- **`void SetupRootOffline(string title, string magiskApk, string zygiskModule, int timeout)`**  
    The same result as `SetupRoot()` — a running, rooted instance with Zygisk live — reached by writing Magisk into the disk images instead of installing it into a running Android.
    
    **Parameters:**
    - `title` — display title as shown in the BlueStacks interface (a system name is accepted too);
    - `magiskApk` — the Magisk `.apk`: both the source of the binaries written into the image and the manager installed afterwards. Empty takes `MagiskSource.DefaultApk`;
    - `zygiskModule` — path to a Zygisk provider module `.zip` (NeoZygisk); `MagiskSource.DefaultZygiskModule` is the copy that ships with ZennoDroid. Empty installs Magisk alone — offline there is no built-in Zygisk to fall back on, since nothing here runs on the device;
    - `timeout` — how long each stop, boot and root wait may take, in seconds.
    
    **Description:**  
    Nothing in it needs root to already exist, so the hex patch of the image, the unpacking of the apk on the device and two of the three restarts all go: the instance is stopped once, both images are written, and the first boot comes up rooted. With `name = TitleToNameConverter(title)`, `bs = new BlueStacks5(name, oem)` and `root = new BlueStacks5Root(name, oem)`, this is exactly what runs:

```csharp
bs.Stop();  bs.WaitForStop(timeout);      // the images have to be free
root.Unlock(patchImage: false);           // clone the system disk, do not patch it
root.InstallMagiskOffline(magiskApk);     // lay Magisk out on the clone
root.InstallModuleOffline(zygiskModule);  // and the Zygisk provider on the data disk
bs.Start(); bs.WaitForBoot(timeout);
root.WaitForRoot(timeout);                // the init trigger brings the daemon up
root.InstallMagisk(magiskApk);            // the manager app, and it goes last
```

One boot, then — except on an instance that has never been started: Android lays `/data` out on its first boot and would take a module written before that along with it, so there the module goes in on a second pass and it takes two.

The manager is installed after that second pass, on the boot the caller is left with, and not before it. What an install carries with it — the icon on the desktop, the permission to post notifications — Android writes when it gets round to it, and an instance stopped moments later comes back without either.

On Android 7 the module is not written at all — that image has no Zygisk — and the rest still runs. Throws if a step fails or a wait runs out of time; the message names the stage it stopped at.

#### Example
```csharp
var mgr = new BlueStacks5Manager("nxt");
mgr.SetupRootOffline("BlueStacks Rvc64", "", "", 120);
```

### Unroot

- **`void Unroot(string title, int timeout)`**  
    Takes root back off the instance — the counterpart of `SetupRoot()` and `SetupRootOffline()`.
    
    **Parameters:**
    - `title` — display title as shown in the BlueStacks interface (a system name is accepted too);
    - `timeout` — how long the stop may take, in seconds.
    
    **Description:**  
    The writable clone of the system disk, the one Magisk was written to, is dropped and the factory image goes back in its place, read-only. `bs.Stop()` + `bs.WaitForStop(timeout)` runs, then `root.Lock()`; the instance is left stopped, because that is the state `Lock()` needs it in and starting it again is the caller's business. Root lives on the system image, so this is all there is to being rid of it: what was written to `/data` — the Magisk manager app among it — stays there and none of it does anything with the binaries gone. An instance that was never rooted is not an error: the disk put back is the one already mounted.

:::note Important Notes
- Before creating/deleting instances, it is recommended to start the manager (`StartManager()`).
- The `cpus` and `ram` parameters must match the host machine's capabilities.
- Incorrect graphics values may lead to unstable behavior.
- Used together with `IBlueStacks5API` for the full cycle: create → start → automate → delete.
:::

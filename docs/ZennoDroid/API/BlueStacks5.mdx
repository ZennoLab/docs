# BlueStacks5 API
<DisclaimerNotice />
## Описание

Набор интерфейсов для управления эмулятором **BlueStacks 5** в ZennoDroid Enterprise.

| Интерфейс | Описание |
|---|---|
| `IBlueStacks5API` | Запуск, остановка и подключение к эмулятору |
| `IBlueStacks5SettingsAPI` | Системные параметры: геолокация, IMEI |
| `IBlueStacks5RootAPI` | Управление root-доступом и Magisk |
| `IBlueStacks5ManagerAPI` | Создание и удаление инстансов через менеджер |

_______________________________________________
## IBlueStacks5API

Управление запуском, остановкой и подключением к эмулятору BlueStacks 5.

### AddressPort

- **`string AddressPort { get; }`**  
    Адрес и порт подключения к эмулятору.
    
    **Возвращает:**  
    Строку в формате `IP:Port` (например: `127.0.0.1:5555`).

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");

string addressPort = bs.AddressPort; // 127.0.0.1:5555
```

---

### IsBootCompleted

- **`bool IsBootCompleted { get; }`**  
    Проверяет, завершена ли загрузка Android внутри эмулятора.
    
    **Возвращает:**  
    `true`, если система полностью загружена и готова к работе.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");

if (!bs.IsBootCompleted)
    throw new Exception("Android ещё не загрузился");
```

---

### IsRunning

- **`bool IsRunning { get; }`**  
    Проверяет, запущен ли эмулятор.
    
    **Возвращает:**  
    `true`, если эмулятор запущен; иначе `false`.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");

if (!bs.IsRunning) bs.Start();
```

---

### Connect

- **`void Connect()`**  
    Подключается к эмулятору (обычно через ADB).

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Connect();
```

---

### Disconnect

- **`void Disconnect()`**  
    Разрывает соединение с эмулятором.

#### Пример.
```csharp
new BlueStacks5("Rvc64_1", "nxt").Disconnect();
```

---

### Start

- **`void Start()`**  
    Запускает эмулятор BlueStacks.

#### Пример.
```csharp
new BlueStacks5("Rvc64_1", "nxt").Start();
```

---

### Stop

- **`void Stop()`**  
    Останавливает эмулятор.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Stop();
bs.WaitForStop(60);
```

---

### WaitForBoot

- **`bool WaitForBoot(int timeout)`**  
    Ожидает завершения загрузки Android: процесс запущен, ADB подключен и `IsBootCompleted` возвращает `true`.
    
    **Параметры:**
    - `timeout` — время ожидания в секундах (`0` — одна проверка без ожидания).
    
    **Возвращает:**  
    `true`, если эмулятор загрузился; `false`, если время истекло.
    
    **Описание:**  
    Вызывайте после каждого `Start()`: тот только просит плеер подняться и возвращает управление сразу, не дожидаясь загрузки.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Start();
if (!bs.WaitForBoot(120)) throw new Exception("Эмулятор не загрузился");
```

---

### WaitForConnect

- **`bool WaitForConnect(int timeout)`**  
    Подключается по ADB и ждёт, пока соединение действительно начнёт отвечать на команды.
    
    **Параметры:**
    - `timeout` — время ожидания в секундах (`0` — одна проверка без ожидания).
    
    **Возвращает:**  
    `true`, если соединение отвечает; `false`, если время истекло.
    
    **Описание:**  
    `Connect()` завершается успешно раньше, чем эмулятор готов отвечать, и первая команда после него возвращает пустой результат или ошибку — этот метод берёт такую команду на себя.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Connect();
if (!bs.WaitForConnect(60)) throw new Exception("Соединение по ADB не отвечает");
```

---

### WaitForStop

- **`bool WaitForStop(int timeout)`**  
    Ожидает, пока процесс эмулятора полностью завершится.
    
    **Параметры:**
    - `timeout` — время ожидания в секундах (`0` — одна проверка без ожидания).
    
    **Возвращает:**  
    `true`, если процесс завершился; `false`, если время истекло.
    
    **Описание:**  
    Вызывайте после каждого `Stop()`: тот только просит плеер завершиться, а диски инстанса остаются заблокированными, пока процесс жив — именно этого ждут операции над остановленным инстансом, в том числе `Unlock()` и `Lock()`.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Stop();
if (!bs.WaitForStop(60)) throw new Exception("Эмулятор не завершился");
```

:::note Важные замечания
- После `Start()` дождитесь загрузки через `WaitForBoot()` (или проверяйте `IsBootCompleted`), прежде чем выполнять действия.
- После `Stop()` дождитесь `WaitForStop()`: пока процесс жив, диски инстанса остаются заблокированными.
- `Connect()` следует вызывать после запуска эмулятора, а готовность соединения проверять через `WaitForConnect()`.
- В некоторых сценариях требуется повторное подключение при сбоях ADB.
:::

## IBlueStacks5SettingsAPI

Изменение системных параметров эмулятора BlueStacks 5.

### SetGeo

- **`void SetGeo(double longitude, double latitude)`**  
    Устанавливает геолокацию устройства.
    
    **Параметры:**
    - `longitude` — долгота (например: `37.6173`);
    - `latitude` — широта (например: `55.7558`).
    
    **Описание:**  
    Позволяет эмулировать нахождение устройства в заданной точке на карте.

#### Пример.
```csharp
new BlueStacks5Settings("Rvc64_1", "nxt").SetGeo(-73.572604, 40.651980);
```

---

### SetIMEI

- **`void SetIMEI(string value)`**  
    Устанавливает IMEI устройства.
    
    **Параметры:**
    - `value` — строковое значение IMEI.
    
    **Описание:**  
    Используется для подмены идентификатора устройства.

#### Пример.
```csharp
new BlueStacks5Settings("Rvc64_1", "nxt").SetIMEI("356938035643809");
```

:::warning Важные замечания
- Некорректные значения IMEI могут вызывать ошибки в приложениях или определяться как недействительные.
- После изменения параметров рекомендуется перезапустить эмулятор и переподключиться.
- Геолокация может дополнительно кешироваться приложениями — иногда требуется их перезапуск.
:::

## IBlueStacks5RootAPI

Управление root-доступом, Magisk и патчами в эмуляторе BlueStacks 5.

### IsRooted

- **`bool IsRooted { get; }`**  
    Проверяет, отвечает ли root на инстансе в данный момент.
    
    **Возвращает:**  
    `true`, если root отвечает; иначе `false`.
    
    **Описание:**  
    Проверка выполняется так же, как её выполняют шаги получения root, поэтому результат верен для любого `su`, который в итоге оказался на инстансе. Для остановленного, ещё загружающегося или просто не рутованного инстанса возвращает `false` и не выбрасывает исключение.

#### Пример.
```csharp
var root = new BlueStacks5Root("Rvc64_1", "nxt");

bool rooted = root.IsRooted;
```

---

### EnableZygisk

- **`void EnableZygisk()`**  
    Включает Zygisk — модуль Magisk для внедрения в процессы через Zygote. Поддерживается на Android 9 (Pie) и выше.
    
    **Описание:**  
    Позволяет использовать продвинутые модули и хуки (например, для обхода детекта root).

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").EnableZygisk();
```

---

- **`void EnableZygisk(string modulePath)`**  
    Включает Zygisk через указанный модуль-провайдер — для сборок Magisk, чей собственный Zygisk не работает в эмуляторе. Модуль сначала устанавливается, затем Zygisk настраивается на обращение к нему.
    
    **Параметры:**
    - `modulePath` — путь к `.zip` модуля-провайдера Zygisk (NeoZygisk).
    
    **Описание:**  
    Изменения вступают в силу после перезапуска эмулятора. На Android 7 вызов отклоняется, а не выполняется вхолостую: в этом образе Zygisk нет вообще, хотя root на нём работает.

#### Пример.
```csharp
var root = new BlueStacks5Root("Rvc64_1", "nxt");
root.EnableZygisk(MagiskSource.DefaultZygiskModule);
```

---

### FlashMagisk

- **`void FlashMagisk()`**  
    Выполняет прошивку (установку) Magisk в систему.
    
    **Описание:**  
    Применяет Magisk на уровне системы после установки.

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").FlashMagisk();
```

---

### InstallMagisk

- **`void InstallMagisk(string path)`**  
    Устанавливает Magisk из указанного файла.
    
    **Параметры:**
    - `path` — путь к файлу Magisk (`.apk`).

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").InstallMagisk(MagiskSource.DefaultApk);
```

---

### InstallMagiskOffline

- **`void InstallMagiskOffline(string magiskApk)`**  
    Раскладывает Magisk по системному образу остановленного разблокированного инстанса, ничего не запуская.
    
    **Параметры:**
    - `magiskApk` — путь к `.apk` Magisk, из которого берутся бинарные файлы.
    
    **Описание:**  
    Заменяет связку `Patch()` + `InstallMagisk()` + `FlashMagisk()` вместе с нужными им перезапусками: root поднимается на следующей загрузке из init-триггера, который записывает этот метод. Инстанс должен быть остановлен (запущенный плеер держит свои образы) и пройти через `Unlock(bool)` — метод пишет в клон системного диска, который создаёт разблокировка. Из apk читаются только бинарные файлы; приложение-менеджер по-прежнему устанавливается методом `InstallMagisk()` на уже загруженном инстансе.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
var root = new BlueStacks5Root("Rvc64_1", "nxt");

bs.Stop();
bs.WaitForStop(60);
root.Unlock(patchImage: false);
root.InstallMagiskOffline(MagiskSource.DefaultApk);
bs.Start();
bs.WaitForBoot(120);
root.WaitForRoot(60);
```

---

### InstallModule

- **`void InstallModule(string path)`**  
    Устанавливает модуль Magisk из указанного zip-файла (LSPosed, Vector и другие).
    
    **Параметры:**
    - `path` — путь к `.zip` модуля.
    
    **Описание:**  
    Модули применяются после перезапуска эмулятора.

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").InstallModule(@"C:\Modules\LSPosed.zip");
```

---

### InstallModuleOffline

- **`bool InstallModuleOffline(string modulePath)`**  
    Помещает модуль-провайдер Zygisk в data-образ остановленного инстанса — так, как разложил бы его установщик самого модуля.
    
    **Параметры:**
    - `modulePath` — путь к `.zip` модуля-провайдера Zygisk.
    
    **Возвращает:**  
    `true`, если модуль записан; `false`, если раздел `/data` ещё ни разу не инициализировался.
    
    **Описание:**  
    Модуль работает уже на следующей загрузке, а не через одну. `false` — не ошибка: значит, писать пока некуда. Android размечает `/data` на самой первой загрузке инстанса и снёс бы всё, записанное до этого, поэтому нужно загрузиться один раз и вызвать метод снова — именно так поступает `SetupRootOffline()`. На Android 7 выбрасывает исключение: обеспечивать там Zygisk нечем.

#### Пример.
```csharp
var root = new BlueStacks5Root("Rvc64_1", "nxt");

if (!root.InstallModuleOffline(MagiskSource.DefaultZygiskModule))
{
    // /data ещё не размечен — загрузиться один раз и повторить вызов
}
```

---

### Lock

- **`void Lock()`**  
    Блокирует root-доступ в эмуляторе. Восстанавливает системный раздел к состоянию без root.
    
    **Описание:**  
    Отключает root, делая систему более «чистой» (например, для обхода проверок приложений).

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
bs.Stop();
bs.WaitForStop(60);

new BlueStacks5Root("Rvc64_1", "nxt").Lock();
```

---

### Patch

- **`void Patch()`**  
    Применяет патч для подготовки системы к работе с root.
    
    **Описание:**  
    Модифицирует системные компоненты эмулятора для поддержки root-доступа.

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").Patch();
```

---

### Unlock

- **`void Unlock()`**  
    Разблокирует root-доступ.
    
    **Описание:**  
    Переводит системный раздел в режим записи. Позволяет вносить изменения для получения root-доступа.

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").Unlock();
```

---

- **`void Unlock(bool patchImage)`**  
    Та же разблокировка, но с выбором, патчить ли системный образ.
    
    **Параметры:**
    - `patchImage` — `true` соответствует поведению `Unlock()`; `false` пропускает патч.
    
    **Описание:**  
    Патч нужен только онлайн-установке root — именно так root получают на **запущенном** инстансе, чтобы можно было копировать файлы. Офлайн-установка передаёт `false` и оставляет образ заводским.

#### Пример.
```csharp
new BlueStacks5Root("Rvc64_1", "nxt").Unlock(patchImage: false);
```

---

### WaitForRoot

- **`bool WaitForRoot(int timeout)`**  
    Ожидает, пока root начнёт отвечать.
    
    **Параметры:**
    - `timeout` — время ожидания в секундах (`0` — одна проверка без ожидания).
    
    **Возвращает:**  
    `true`, если root отвечает; `false`, если время истекло.
    
    **Описание:**  
    Root появляется не в тот момент, когда Android сообщает о завершении загрузки: демон `su` поднимается сам через несколько секунд, поэтому единственная проверка `IsRooted` сразу после перезапуска ничего не говорит.

#### Пример.
```csharp
var bs = new BlueStacks5("Rvc64_1", "nxt");
var root = new BlueStacks5Root("Rvc64_1", "nxt");

bs.Start();
bs.WaitForBoot(120);
if (!root.WaitForRoot(60)) throw new Exception("Root не поднялся");
```

:::warning Важные замечания
- Операции с root могут повлиять на стабильность эмулятора или нарушить работу приложений.
- После изменений рекомендуется перезапуск эмулятора и проверка состояния root.
- Используется совместно с [`IFridaDeviceAPI`](./Frida), [`IDroidAppAPI`](./App) и `RootShell` ([`IDroidInputAPI`](./Input#rootshell)).
:::

## IBlueStacks5ManagerAPI

Управление инстансами BlueStacks 5 через менеджер: создание, удаление, запуск/остановка службы.

**Конструктор:** `BlueStacks5Manager(string oem)`

- `oem` — строка, идентифицирующая версию BlueStacks:
    - `"nxt"` — стандартная версия
    - `"nxt_cn"` — версия для Китая
    - `"msi5"` — версия от MSI (MSI App Player 5)

### Create

- **`string Create(string imageName, int cpus, int ram, string graphicEngine, string graphicRenderer, string deviceProfile, string abiList)`**  
    Создаёт новый экземпляр эмулятора с заданными параметрами.
    
    **Параметры:**
    - `imageName` — базовый образ эмулятора:
        - `"Nougat32"` — Android 7.1 (x86)
        - `"Nougat64"` — Android 7.1 (x64)
        - `"Pie64"` — Android 9.0 (x64)
        - `"Rvc64"` — Android 11.0 (x64)
        - `"Tiramisu64"` — Android 13.0 (x64)
    - `cpus` — количество выделенных CPU;
    - `ram` — объём оперативной памяти (МБ);
    - `graphicEngine` — графический движок (только для Android 7):
        - `"aga"` — Compatibility
        - `"pga"` — Performance
    - `graphicRenderer` — тип рендера:
        - `"gl"` — OpenGL
        - `"dx"` — DirectX
        - `"vlcn"` — Vulkan
    - `deviceProfile` — профиль устройства:
        - `"rogt"` — Asus ROG 2
        - `"ptxg"` — Google Pixel 2XL
        - `"optp"` — OnePlus 10 Pro
        - `"opet"` — OnePlus 8T
        - `"anfg"` — Samsung Galaxy A90 5G
        - `"smtn"` — Samsung Galaxy S10
        - `"stfg"` — Samsung Galaxy S10 5G
        - `"stul"` — Samsung Galaxy S20 Ultra
        - `"stwp"` — Samsung Galaxy S20+
        - `"stou"` — Samsung Galaxy S21 Ultra
        - `"sstt"` — Samsung Galaxy S22
        - `"sttu"` — Samsung Galaxy S22 Ultra
        - `"xitp"` — Xiaomi 11T Pro
    - `abiList` — список поддерживаемых ABI (например: `"x86,x64,arm,arm64"`).
    
    **Возвращает:**  
    Имя созданного инстанса.

#### Пример.
```csharp
var name = new BlueStacks5Manager("nxt").Create("Rvc64", 
	cpus:2, 
	ram:2048,
	graphicEngine:"aga",
	graphicRenderer:"dx",
	deviceProfile:"xitp", 
	abiList:"x86,x64,arm,arm64");
```

---

### DeleteByName

- **`void DeleteByName(string name)`**  
    Удаляет экземпляр эмулятора по имени.
    
    **Параметры:**
    - `name` — имя инстанса.

#### Пример.
```csharp
new BlueStacks5Manager("nxt").DeleteByName("Rvc64_1");
```

---

### Exists

- **`bool Exists(string name)`**  
    Проверяет, существует ли инстанс с указанным системным именем.
    
    **Параметры:**
    - `name` — системное имя инстанса.
    
    **Возвращает:**  
    `true`, если такой инстанс зарегистрирован.
    
    **Описание:**  
    Обращение к несуществующему инстансу — `new BlueStacks5(name)` и подобные — это ошибка, поэтому спрашивать следует заранее.

#### Пример.
```csharp
var mgr = new BlueStacks5Manager("nxt");

if (!mgr.Exists("Rvc64_1")) throw new Exception("Инстанс не найден");
```

---

### GetListNames

- **`string[] GetListNames()`**  
    Системные имена всего, что зарегистрировано для данного OEM.
    
    **Возвращает:**  
    Массив системных имён.
    
    **Описание:**  
    В список входят и базовые образы — именно из них клонируются новые инстансы, и перечисляются они так же, как обычный инстанс.

#### Пример.
```csharp
var mgr = new BlueStacks5Manager("nxt");

foreach (var name in mgr.GetListNames())
    project.SendInfoToLog(name); // Rvc64, Rvc64_1, Pie64, ...
```

---

### GetListTitles

- **`string[] GetListTitles()`**  
    Отображаемые названия того же списка.
    
    **Возвращает:**  
    Массив названий в том же порядке, что и у `GetListNames()`.

#### Пример.
```csharp
var mgr = new BlueStacks5Manager("nxt");

var names = mgr.GetListNames();
var titles = mgr.GetListTitles();

for (int i = 0; i < names.Length; i++)
    project.SendInfoToLog($"{titles[i]} -> {names[i]}");
```

### SetupRoot

- **`void SetupRoot(string title, string magiskApk, string zygiskModule, int timeout)`**  
    Выполняет весь сценарий получения root на инстансе и оставляет его запущенным, рутованным, с работающим Zygisk.
    
    **Параметры:**
    - `title` — отображаемое название инстанса, как оно показано в интерфейсе BlueStacks (системное имя тоже принимается);
    - `magiskApk` — путь к `.apk` Magisk. Пустая строка берёт `MagiskSource.DefaultApk` — копию, поставляемую с ZennoDroid;
    - `zygiskModule` — путь к `.zip` модуля-провайдера Zygisk (NeoZygisk), который нужен сборкам Magisk с неработающим в эмуляторе собственным Zygisk; `MagiskSource.DefaultZygiskModule` — копия из состава ZennoDroid. Пустая строка включает собственный Zygisk Magisk;
    - `timeout` — предельное время каждого ожидания в сценарии, в секундах.
    
    **Описание:**  
    Каждый шаг сценария и каждое ожидание в нём — отдельный метод этого API, поэтому то же самое можно сделать по шагам. При `name = TitleToNameConverter(title)`, `bs = new BlueStacks5(name, oem)` и `root = new BlueStacks5Root(name, oem)` выполняется ровно следующее:

```csharp
bs.Stop();  bs.WaitForStop(timeout);   // Unlock требует, чтобы диски были свободны
root.Unlock();
bs.Start(); bs.WaitForBoot(timeout);   // Patch требует загруженного Android
root.Patch();
root.InstallMagisk(magiskApk);
root.FlashMagisk();
bs.Stop();  bs.WaitForStop(timeout);   // демон Magisk поднимается только при загрузке
bs.Start(); bs.WaitForBoot(timeout);
if (!root.WaitForRoot(timeout))        // нужно ли повторять Patch — см. ниже
    root.Patch();
root.EnableZygisk(zygiskModule);
bs.Stop();  bs.WaitForStop(timeout);   // загрузчик Zygisk подхватывает только тот zygote,
bs.Start(); bs.WaitForBoot(timeout);   // который стартовал после демона
```

Root — это bind-mount'ы, а они не выживают перезагрузку, поэтому с некоторыми сборками Magisk патч приходится накладывать заново после перезапуска. Но системная прошивка upstream-Magisk ставит boot-триггер, который восстанавливает его сам, и патч поверх этого только мешает — поэтому нужный вариант выясняется через `WaitForRoot()`, а не предполагается.

На Android 7 шаг с Zygisk пропускается, а всё, что до него, всё равно выполняется: в этом образе Zygisk нет, а root на нём полезен сам по себе.

Выбрасывает исключение, если шаг не удался или истекло время ожидания; в сообщении указан этап, на котором сценарий остановился.

#### Пример.
```csharp
var mgr = new BlueStacks5Manager("nxt");
mgr.SetupRoot("BlueStacks Rvc64", "", "", 120);
```

### SetupRootOffline

- **`void SetupRootOffline(string title, string magiskApk, string zygiskModule, int timeout)`**  
    Тот же результат, что у `SetupRoot()` — запущенный рутованный инстанс с работающим Zygisk, — но достигнутый записью Magisk прямо в образы дисков, а не установкой в запущенный Android.
    
    **Параметры:**
    - `title` — отображаемое название инстанса, как оно показано в интерфейсе BlueStacks (системное имя тоже принимается);
    - `magiskApk` — `.apk` Magisk: и источник бинарных файлов для образа, и менеджер, который ставится после. Пустая строка берёт `MagiskSource.DefaultApk`;
    - `zygiskModule` — путь к `.zip` модуля-провайдера Zygisk (NeoZygisk); `MagiskSource.DefaultZygiskModule` — копия из состава ZennoDroid. Пустая строка устанавливает один Magisk: офлайн отступать на встроенный Zygisk некуда, ведь на устройстве здесь ничего не выполняется;
    - `timeout` — предельное время каждой остановки, загрузки и ожидания root, в секундах.
    
    **Описание:**  
    Ничему здесь не нужен уже полученный root, поэтому hex-патч образа, распаковка apk на устройстве и два перезапуска из трёх не нужны: инстанс останавливается один раз, оба образа записываются, и первая же загрузка поднимается рутованной. При `name = TitleToNameConverter(title)`, `bs = new BlueStacks5(name, oem)` и `root = new BlueStacks5Root(name, oem)` выполняется ровно следующее:

```csharp
bs.Stop();  bs.WaitForStop(timeout);      // образы должны быть свободны
root.Unlock(patchImage: false);           // клонировать системный диск, не патчить его
root.InstallMagiskOffline(magiskApk);     // разложить Magisk по клону
root.InstallModuleOffline(zygiskModule);  // а провайдер Zygisk — по data-диску
bs.Start(); bs.WaitForBoot(timeout);
root.WaitForRoot(timeout);                // init-триггер поднимает демон
root.InstallMagisk(magiskApk);            // приложение-менеджер, и оно идёт последним
```

То есть одна загрузка — кроме инстанса, который ещё ни разу не запускали: `/data` Android размечает на первой загрузке и снёс бы модуль, записанный до неё, поэтому там модуль записывается вторым проходом и загрузок выходит две.

Менеджер ставится после этого второго прохода, на той загрузке, с которой остаётся работать вызывающий, а не раньше. То, что установка приносит с собой — иконку на рабочем столе, разрешение на уведомления, — Android записывает, когда дойдёт до этого, и инстанс, остановленный через несколько мгновений, вернётся без того и другого.

На Android 7 модуль не записывается вовсе — в этом образе нет Zygisk, — а всё остальное выполняется. Выбрасывает исключение, если шаг не удался или истекло время ожидания; в сообщении указан этап, на котором сценарий остановился.

#### Пример.
```csharp
var mgr = new BlueStacks5Manager("nxt");
mgr.SetupRootOffline("BlueStacks Rvc64", "", "", 120);
```

### Unroot

- **`void Unroot(string title, int timeout)`**  
    Снимает root с инстанса — обратная операция к `SetupRoot()` и `SetupRootOffline()`.
    
    **Параметры:**
    - `title` — отображаемое название инстанса, как оно показано в интерфейсе BlueStacks (системное имя тоже принимается);
    - `timeout` — предельное время остановки, в секундах.
    
    **Описание:**  
    Записываемый клон системного диска, тот, в который был установлен Magisk, удаляется, а на его место возвращается заводской образ в режиме только для чтения. Выполняется `bs.Stop()` + `bs.WaitForStop(timeout)`, затем `root.Lock()`; инстанс остаётся остановленным, потому что именно в этом состоянии `Lock()` его и требует, а запускать его снова — дело вызывающего. Root живёт на системном образе, поэтому этого достаточно: записанное в `/data` (в том числе приложение-менеджер Magisk) остаётся, но без бинарных файлов ничего не делает. Инстанс, который никогда не был рутован, — не ошибка: возвращается тот же образ, что и был смонтирован.

#### Пример.
```csharp
new BlueStacks5Manager("nxt").Unroot("BlueStacks Rvc64", 120);
```

:::note Важные замечания
- Перед созданием/удалением инстансов рекомендуется запустить менеджер (`StartManager()`).
- Параметры `cpus` и `ram` должны соответствовать возможностям хост-машины.
- Некорректные значения графики могут привести к нестабильной работе.
- Используется совместно с `IBlueStacks5API` для полного цикла: создание → запуск → автоматизация → удаление.
:::

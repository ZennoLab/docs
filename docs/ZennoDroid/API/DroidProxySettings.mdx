# DroidProxySettings
<DisclaimerNotice />

## Описание

`IDroidProxySettings` определяет настройки прокси и защиты от утечек сетевых данных на Android-устройстве в ZennoDroid. Используется для повышения анонимности и контроля сетевого трафика.

Имеет несколько реализаций (вариантов настройки), в зависимости от способа проксирования.

_______________________________________________

## DroidProxySettings.Proxifier

Базовые настройки прокси с использованием механизма проксирования трафика.

- **`bool? BlockWebRtcLeak { get; set; }`**  
    Включает или отключает защиту от утечек через WebRTC.
    
    **Описание:**  
    Предотвращает раскрытие реального IP-адреса через WebRTC (используется в браузерах и WebView).

---

- **`bool? BlockUDPLeak { get; set; }`**  
    Включает или отключает защиту от UDP-утечек.
    
    **Описание:**  
    Блокирует UDP-трафик, который может обходить прокси и раскрывать реальный IP.

---

- **`DroidIpv6Mode? Ipv6Mode { get; set; }`**  
    Что туннель телефона делает с IPv6.
    
    **Описание:**  
    Значение из перечисления [`DroidIpv6Mode`](#droidipv6mode). Если не задано, берётся из настроек ZennoDroid, по умолчанию `Tunnel`. На эмуляторах не используется. Доступно начиная с версии ZennoDroid 2.6.3.0.

---

- **`string Nat64Prefix { get; set; }`**  
    Префикс шлюза NAT64.
    
    **Описание:**  
    Только `/96`, например `2a01:4f9:c010:3f02:64::/96`. Нужен для прокси, который работает только по IPv6 и не пускает к IPv4-адресам: к ним туннель телефона ходит через шлюз. Если не задан, берётся из настроек ZennoDroid. Префикс другой длины не применяется, а в лог пишется ошибка. Доступно начиная с версии ZennoDroid 2.6.3.0.

---

- **`bool? DnsOverTcp { get; set; }`**  
    Как туннель телефона передаёт DNS-запросы.
    
    **Описание:**  
    `true` - по TCP через прокси, такие запросы пропускает любой прокси; `false` - UDP-датаграммами, которые проходят только через SOCKS5 с поддержкой UDP. Если не задано, берётся из настроек ZennoDroid, по умолчанию `true`. Доступно начиная с версии ZennoDroid 2.6.3.0.

## DroidProxySettings.ProxifierViaPC

Расширенные настройки прокси при использовании проксирования через ПК.

- **`bool? BlockWebRtcLeak { get; set; }`**  
    Управляет защитой от WebRTC-утечек.

---

- **`bool? BlockUDPLeak { get; set; }`**  
    Управляет блокировкой UDP-утечек.

---

- **`string DnsServers { get; set; }`**  
    Указывает DNS-серверы.
    
    **Описание:**  
    Позволяет задать пользовательские DNS (например: `8.8.8.8, 1.1.1.1`).

---

- **`string LocalIPv4Address { get; set; }`**  
    Локальный IPv4-адрес.
    
    **Описание:**  
    Используется для привязки прокси к конкретному сетевому интерфейсу ПК.

---

- **`string LocalIPv6Address { get; set; }`**  
    IPv6-адрес туннеля с длиной префикса.
    
    **Описание:**  
    Например, `fdfe:dcba:0::1/126`. Если не задан, берётся из настроек ZennoDroid. Доступно начиная с версии ZennoDroid 2.6.3.0.

## DroidProxySettings.ProxyBridge

:::info **Доступно начиная с версии ZennoDroid 2.6.3.0.**
:::

Настройки способа [**ProxyBridge**](../Settings/Proxy_Traffic_Ent#proxybridge) - альтернативы Proxifier, при которой мимо прокси не уходит и UDP. На телефоне трафик всегда идёт через интернет-подключение компьютера, на эмуляторе (MEmu, LDPlayer, MuMu) проксируется процесс эмулятора. Поля DNS, локальных адресов, IPv6 и NAT64 используются только на телефоне. Незаданное свойство берётся из настроек ZennoDroid.

- **`bool? BlockWebRtcLeak { get; set; }`**  
    Защита от утечек через WebRTC. По умолчанию `true`.

---

- **`bool? BlockUDPLeak { get; set; }`**  
    Если прокси не поддерживает UDP, дополнительно отсекает на устройстве UDP-трафик на порт 443 (QUIC). По умолчанию `true`. Мимо прокси UDP не уходит и при `false`.

---

- **`string DnsServers { get; set; }`**  
    DNS-серверы, например `8.8.8.8,8.8.4.4`. Можно указать и IPv6-адрес сервера.

---

- **`string LocalIPv4Address { get; set; }`**  
    Локальный IPv4-адрес телефона. Если последнее число равно нулю (по умолчанию `192.168.10.0`), выбирается случайный адрес этой подсети.

---

- **`string LocalIPv6Address { get; set; }`**  
    IPv6-адрес туннеля с длиной префикса, по умолчанию `fdfe:dcba:0::1/126`.

---

- **`DroidIpv6Mode? Ipv6Mode { get; set; }`**  
    Что туннель делает с IPv6, по умолчанию `Tunnel`. Значения - в разделе [`DroidIpv6Mode`](#droidipv6mode).

---

- **`string Nat64Prefix { get; set; }`**  
    Префикс шлюза NAT64 (только `/96`) для прокси, который работает только по IPv6.

---

- **`bool? DnsOverTcp { get; set; }`**  
    `true` (по умолчанию) - DNS телефона идёт по TCP через прокси; `false` - UDP-датаграммами, которые проходят только через SOCKS5 с поддержкой UDP.

#### Пример.  
```csharp
var settings = new DroidProxySettings.ProxyBridge();
settings.DnsServers = "8.8.8.8";
instance.DroidInstance.Proxy.SetProxy("socks5://login:pass@1.2.3.4:1080", settings);
```

## DroidIpv6Mode

:::info **Доступно начиная с версии ZennoDroid 2.6.3.0.**
:::

Что туннель телефона делает с IPv6 в способах Proxifier и ProxyBridge (свойство `Ipv6Mode`):
- `Tunnel` - IPv6 идёт через туннель и прокси. Значение по умолчанию. Если прокси открывает IPv6-адрес, у телефона есть настоящий IPv6, а если нет - соединение отклоняется за несколько секунд, и приложение переходит на IPv4. Мимо туннеля ничего не уходит.  
- `Block` - IPv6 отбрасывается в туннеле. Утечек нет, но телефону никто не отвечает, и приложение переходит на IPv4 только по своему тайм-ауту.  
- `Bypass` - IPv6 остаётся Android: он идёт мимо туннеля, с настоящим адресом телефона.

## DroidProxySettings.Redsocks

Настройки прокси через **Redsocks** (перенаправление TCP/UDP трафика через прокси).

- **`string DnsServers { get; set; }`**  
    DNS-серверы.
    
    **Описание:**  
    Указывает список DNS (например: `8.8.8.8, 1.1.1.1`).

---

- **`bool? UseDnsTcp { get; set; }`**  
    Использовать DNS через TCP.
    
    **Описание:**  
    Перенаправляет DNS-запросы по TCP вместо UDP.

---

- **`bool? UseDnsUdp { get; set; }`**  
    Использовать DNS через UDP.
    
    **Описание:**  
    Использовать DNS через прокси.

---

- **`bool? BlockWebRtcLeak { get; set; }`**  
    Блокировка WebRTC-утечек.

---

- **`bool? BlockUDPLeak { get; set; }`**  
    Блокировка UDP-утечек.

---

- **`string WebRtcLeakAddresses { get; set; }`**  
    Адреса для обработки WebRTC.
    
    **Описание:**  
    Список IP/адресов, используемых для контроля или подмены WebRTC-трафика.

---

- **`string WebUdpLeakAddresses { get; set; }`**  
    Адреса для обработки UDP-утечек.
    
    **Описание:**  
    Список IP/адресов для контроля UDP-трафика.

## DroidProxySettings.Clash

Настройки прокси через **Clash** — продвинутый прокси-клиент с поддержкой правил маршрутизации трафика.

- **`string DnsServers { get; set; }`**  
    DNS-серверы.
    
    **Описание:**  
    Указывает список DNS (например: `8.8.8.8, 1.1.1.1`). Адреса разделяются запятой, точкой с запятой, пробелом или переносом строки. Серверы с префиксом `tcp://`, `tls://` или `https://` Clash опрашивает через прокси, серверы без префикса и с `udp://` - напрямую.

---

- **`string LocalIPv4Address { get; set; }`**  
    Локальный IPv4-адрес.
    
    **Описание:**  
    Задает локальный IPv4-адрес.

---

- **`string LocalIPv6Address { get; set; }`**  
    Локальный IPv6-адрес.
    
    **Описание:**  
    Задает локальный IPv6-адрес.

---

- **`string WhiteList { get; set; }`**  
    Белый список.
    
    **Описание:**  
    Список приложений, трафик которых будет идти через прокси. Идентификаторы приложений разделяются запятой, точкой с запятой, пробелом или переносом строки.

---

- **`string BlackList { get; set; }`**  
    Чёрный список.
    
    **Описание:**  
    Список приложений, трафик которых будет идти напрямую, минуя прокси. Идентификаторы разделяются так же, как в `WhiteList`.

---

- **`string NetworkMode { get; set; }`**  
    Режим работы сети.
    
    **Описание:**  
    Определяет стратегию маршрутизации:
    - `redirect` — handles tcp + udp[direct]
    - `tproxy` — handles tcp + udp
    - `mixed` — redirect[tcp] + tun[udp]
    - `enhance` — redirect[tcp] + tproxy[udp]
    - `tun` — handles tcp + udp (auto-route)

---

- **`string Rules { get; set; }`**  
    Правила маршрутизации.
    
    **Описание:**  
    Набор правил (в формате Clash), определяющих, какой трафик куда направлять.

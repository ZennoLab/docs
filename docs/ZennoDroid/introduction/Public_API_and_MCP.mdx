# Публичный API и MCP-серверы

<DisclaimerNotice />

В версии 2.6.1 у ZennoDroid и ProjectMaker появились публичный HTTP API (PublicApi) и комплект публичных MCP-серверов. Продуктом можно управлять извне: из собственных скриптов и приложений или из ИИ-ассистента. Права доступа задаёт ваш API-ключ.

:::info Требования
ZennoDroid 2.6.1 или новее, Windows x64. Какие версии серверов подходят к вашей версии ZennoDroid, указано в [таблице совместимости](https://zennolab.github.io/zennoposter-mcp/ru/compatibility.html). Для работы с проектом должен быть запущен ProjectMaker с открытым проектом, для работы с задачами — ZennoDroid.
:::

_______________________________________________

## 1. Что появилось в 2.6.1

**Публичный REST API (PublicApi)** — более 100 операций под единым контрактом:

- работа с проектом в ProjectMaker: дерево действий, переменные, списки, таблицы, статические данные;
- управление задачами и сессиями выполнения в ZennoDroid;
- информация с устройства: дерево элементов экрана, установленные приложения.

Контракт описан в OpenAPI, по спецификации можно сгенерировать клиент для любого языка.

**API-ключи с гибкими правами.** Ключи выпускаются в ProjectMaker, для каждого задаётся набор разрешений и максимальный уровень операций, от строго read-only до полного управления.

**Публичные MCP-серверы** поверх этого API: скачали, вписали свой ключ, подключили к своему ИИ-клиенту. Права ассистента определяются вашим ключом, подключения принимаются только с локальной машины.

Встроенный ИИ-чат продукта работает на этой же инфраструктуре: тот же API и та же модель прав, скрытых привилегированных каналов нет. Про сам чат читайте в статье [ИИ-помощник](./ai-assistant).

_______________________________________________

## 2. Два набора MCP-серверов

Это главное, что нужно понять перед настройкой. Серверов два комплекта, и они решают разные задачи.

| | Внутренние серверы | Публичные серверы |
|---|---|---|
| **Порты** | `6117` ProjectMCP, `6118` AndroidMCP | `6211`, `6212`, `6217`, `6220` |
| **Запуск** | Автоматически вместе с ProjectMaker | Вручную, скачиваются отдельно |
| **API-ключ** | Служебный, выдаёт сам продукт | Ваш, права задаёте вы |
| **Охват** | Проект и устройство ProjectMaker | Проект и устройство ProjectMaker, задачи ZennoDroid и их устройства |
| **Внешние ассистенты** | Не принимаются с версии 2.6.2 | Подключаются, для этого и нужны |
| **Настройка** | Не требуется | Эта страница и [Настройка MCP для AI-ассистентов](./MCP_Setup) |

Внутренние серверы обслуживают только встроенный ИИ-чат. С версии 2.6.2 они отклоняют запросы внешних клиентов: ошибка `401`, в логе продукта запись `ingress refused`. Если ваш ассистент был подключён к `6117` или `6118`, переключите его на публичные серверы.

Публичные серверы работают рядом со встроенными и не мешают им. Права ассистента задаёт ваш ключ: можно оставить только чтение проекта или открыть управление задачами ZennoDroid.

Порты ZennoDroid сдвинуты на +10 относительно ZennoPoster, поэтому серверы обоих продуктов работают на одной машине одновременно. Исключение — MCP.Android: он есть только у ZennoDroid и занимает `6211` и `6212`.

:::warning Не занимайте порты 6117-6123
На этом диапазоне работает внутренняя инфраструктура продукта. Не запускайте на них свои процессы, иначе встроенный ИИ-чат перестанет работать.
:::

## 3. API-ключи: права и уровни

Ключ выпускается в ProjectMaker: **Редактирование → Настройки → API-ключи → Добавить новый API-ключ**. В окне задаются:

- **Название** — имя, по которому вы потом поймёте, кому выдан ключ.
- **Макс. уровень** — потолок серьёзности операций. `T0` разрешает только чтение, уровни выше открывают изменения.
- **Истекает** — через сколько дней ключ перестанет действовать, `0` — бессрочно.
- **Разрешения** — набор областей доступа. По умолчанию отмечены только разрешения на чтение.

Ключ создаётся кнопкой **Сгенерировать ключ**.

:::caution Ключ показывается один раз
Скопируйте ключ сразу при создании и сохраните. Посмотреть его заново нельзя, потерянный ключ проще удалить и выпустить новый.
:::

Если ключу не хватает прав, API возвращает ошибку, в которой указано, какого именно разрешения или уровня не хватило.

**Рекомендуемый порядок работы:**

1. Выпустите ключ с уровнем `T0` и разрешениями только на чтение.
2. Убедитесь, что ассистент видит проект и отвечает на вопросы по нему.
3. Выпустите второй ключ с разрешениями на запись и используйте его, когда нужны правки.

Отдельный ключ на каждого клиента и каждую машину упрощает отзыв: при проблеме понятно, что именно удалять.

## 4. Установка публичных серверов

### Шаг 1. Выберите нужные серверы

| Задача | Сервер | Порт |
|---|---|---|
| Читать и править проект: кубики, связи, переменные, списки, таблицы | MCP.ProjectMaker | `6217` |
| Запускать устройство ProjectMaker и смотреть его экран, элементы и приложения | MCP.Android | `6211` |
| Ставить и вести задачи: запуск, потоки, остановка, логи | MCP.ZennoPoster | `6220` |
| Смотреть устройства выполняющихся задач | MCP.Android, вторая копия | `6212` |

Ставить все сразу не нужно. Если начинаете с одного сервера, берите **MCP.ProjectMaker**.

### Шаг 2. Скачайте и распакуйте

Архивы лежат на [странице релизов](https://github.com/ZennoLab/zennoposter-mcp/releases) и называются по образцу `MCP.ProjectMaker-v0.6.0-win-x64.zip`. Распакуйте каждый в свою папку, например `C:\ZennoMCP\ProjectMaker`. Это готовые самодостаточные сборки, отдельная установка .NET не требуется.

### Шаг 3. Запустите сервер со своим ключом

Откройте папку с распакованным сервером, напишите в адресной строке проводника `powershell` и нажмите Enter. Подставьте свой ключ вместо `zp_xxx`. MCP.ProjectMaker и MCP.ZennoPoster без аргументов запускаются для ZennoPoster, поэтому в командах для ZennoDroid указаны порт и адрес продукта.

```powershell title="ProjectMaker, порт 6217"
.\ZennoLab.AI.MCP.ProjectMaker.exe --urls http://localhost:6217 `
  --ProjectMaker:BaseUrl=http://localhost:5309/api/v1 --ProjectMaker:ApiKey=zp_xxx
```

```powershell title="Устройство в ProjectMaker, порт 6211"
.\ZennoLab.AI.MCP.Android.exe --Android:ApiKey=zp_xxx
```

```powershell title="Задачи ZennoDroid, порт 6220"
.\ZennoLab.AI.MCP.ZennoPoster.exe --urls http://localhost:6220 `
  --ZennoPoster:BaseUrl=http://localhost:5310/api/v1 --ZennoPoster:ApiKey=zp_xxx
```

Окно консоли должно оставаться открытым: без запущенного сервера ассистент теряет доступ.

:::tip Запуск без ввода ключа
Значения из команды можно вписать в файл `appsettings.json` рядом с программой, тогда сервер запускается двойным кликом по exe. MCP.Android хватит ключа в поле `ApiKey`, а для MCP.ProjectMaker и MCP.ZennoPoster впишите ещё порт и адрес продукта. Например, для MCP.ProjectMaker:

```json
{
  "Urls": "http://localhost:6217",
  "ProjectMaker": {
    "BaseUrl": "http://localhost:5309/api/v1",
    "ApiKey": "zp_xxx"
  }
}
```

Ключ также можно передать переменной окружения вида `ProjectMaker__ApiKey`. Аргумент командной строки имеет приоритет над переменной окружения и файлом настроек.
:::

### Устройства выполняющихся задач, порт 6212

Это вторая копия сервера MCP.Android с другими параметрами. Распакуйте архив во вторую папку и запускайте так:

```powershell
.\ZennoLab.AI.MCP.Android.exe --urls http://localhost:6212 `
  --Android:Target=zennoposter --Android:BaseUrl=http://localhost:5310/api/v1 `
  --Android:ApiKey=zp_xxx
```

## 5. Подключение ИИ-клиента

Готовые кнопки установки для Cursor и VS Code и команды для Claude Code собраны на [странице установки](https://zennolab.github.io/zennoposter-mcp/ru/install.html), серверы ZennoDroid там в отдельной таблице. Ниже то же самое вручную. Оставьте строки только для тех серверов, которые запустили.

### Claude Code

```sh
claude mcp add --scope user --transport http projectmaker-droid http://localhost:6217
claude mcp add --scope user --transport http android-pm http://localhost:6211
claude mcp add --scope user --transport http zennodroid http://localhost:6220
claude mcp add --scope user --transport http android-zd http://localhost:6212
claude mcp list
```

С `--scope user` серверы доступны во всех папках, без него — только в текущей.

### GitHub Copilot, Cursor, VS Code

В Cursor и VS Code серверы проще всего добавить кнопками со [страницы установки](https://zennolab.github.io/zennoposter-mcp/ru/install.html). Для GitHub Copilot в Visual Studio добавьте в файл `.mcp.json` в папке профиля (`Win + R` → `%USERPROFILE%`):

```json
{
  "servers": {
    "projectmaker-droid": { "type": "http", "url": "http://localhost:6217" },
    "android-pm": { "type": "http", "url": "http://localhost:6211" },
    "zennodroid": { "type": "http", "url": "http://localhost:6220" },
    "android-zd": { "type": "http", "url": "http://localhost:6212" }
  }
}
```

После правки файла перезапустите клиента: конфигурация читается при старте.

### LM Studio, локальная модель

Нужна версия LM Studio 0.3.17 или новее, в более ранних поддержки MCP нет. Модель выбирайте с поддержкой вызова инструментов (tool use), иначе она не сможет выполнять команды. Блок добавляется в файл `mcp.json` через редактор внутри программы (**Program → Install → Edit mcp.json**), раздел там называется иначе:

```json
{
  "mcpServers": {
    "projectmaker-droid": { "url": "http://localhost:6217" }
  }
}
```

:::note
Локальные модели слабее облачных: чаще теряются в больших проектах и иногда вызывают не те инструменты. Для чтения и объяснения проекта их хватает, для сложных правок лучше облачная модель.
:::

### Проверка подключения

Напишите ассистенту:

```text
Какие инструменты ZennoDroid тебе доступны? Перечисли их.
```

Если он перечислил список инструментов, всё работает.

## 6. Что умеет внешний ассистент

### Проект

- Читает проект как граф: какие в нём кубики, как они связаны и куда ведут ветки ошибок. Строит маршрут между двумя кубиками и показывает все связи выбранного кубика. Поэтому ассистент отвечает на вопросы вида «как выполнение доходит до этого кубика» и «что сломается, если убрать эту ветку».
- Добавляет, меняет и удаляет кубики, работает с переменными, списками, таблицами и статическими данными проекта.
- Сохраняет проект и подтверждает, что файл на диске обновился. Проект с несохранёнными правками ассистент не закрывает, чтобы работа не пропала молча: закрыть его без сохранения можно, только если прямо попросить об этом.

### Устройство

- Запускает устройство ProjectMaker, узнаёт разрешение экрана, читает элементы текущего экрана и список установленных приложений. То же чтение доступно для устройств выполняющихся задач.
- Нажимать и вводить текст на устройстве сервер не умеет. Действия на устройстве — это кубики проекта: ассистент добавляет их через сервер проекта, а выполняются они при запуске проекта. Подробнее — в статье [Настройка MCP для AI-ассистентов](./MCP_Setup#1-чем-zennodroid-mcp-отличается-от-zennoposter-mcp).

### Задачи

- Задачи ZennoDroid: запуск, потоки, остановка, статусы, логи.
- Окна «Ожидание действий пользователя»: ассистент видит открытые окна и может их закрыть.

Полный справочник операций, коды ошибок и политика версий собраны в [документации по PublicApi](https://zennolab.github.io/zennoposter-mcp/ru/).

## 7. Примеры запросов

Начинайте с чтения: так видно, насколько ассистент разобрался в проекте, и ничем не рискуете.

**Разобраться в проекте:**

```text
Опиши по шагам, что делает открытый проект. Где он может упасть?

Построй маршрут от стартового кубика до кубика, который запускает приложение.

Покажи все входящие и исходящие связи выделенного кубика и куда ведут ветки ошибок.
```

**Собрать шаг по экрану устройства:**

```text
Прочитай структуру текущего экрана, найди поле ввода телефона
и добавь в проект кубик, который вводит в него {-Variable.phone-}.
```

**Править и отлаживать:**

```text
Найди кубики, у которых не заполнена ветка OnError, и предложи, что туда поставить.

Сохрани проект и подтверди, что файл на диске обновился.
```

**Запускать и разбирать падения:**

```text
Запусти эту задачу в 3 потока, дождись завершения и покажи, на каком кубике
она упала и какие значения были у переменных в этот момент.
```

:::tip
Перед правками через ассистента сохраните копию проекта: изменения приходят быстро и пачками.
:::

## 8. Устранение неполадок

| Симптом | Причина | Что делать |
|---|---|---|
| Клиент говорит, что инструментов нет | Сервер не запущен или конфигурация прописана не в ту программу | Проверьте окно сервера и перезапустите клиента: конфигурация читается при старте |
| Ошибка `401` | Ключ неверный или не подставился | Проверьте, что ключ указан целиком, без лишних пробелов и кавычек. Если ключ потерян, выпустите новый |
| Ошибка `401` на порту `6117` или `6118` | Клиент подключён к встроенному серверу, с 2.6.2 он не принимает внешних клиентов | Запустите свою копию сервера и укажите в клиенте её порт: `6211`, `6212`, `6217` или `6220` |
| Ошибка `403` | Ключу не хватает разрешения или уровня | В тексте ошибки указано, чего именно не хватило. Выпустите ключ с нужными разрешениями и уровнем выше `T0` |
| Ошибка `409` при закрытии проекта | В проекте есть несохранённые правки | Сохраните проект или прямо попросите ассистента закрыть его без сохранения |
| Ассистент видит проект ZennoPoster, а не ZennoDroid | Клиент подключён к порту ZennoPoster (`6207`-`6210`) | Укажите в клиенте порт ZennoDroid и запустите сервер командой из шага 3 |
| Сервер не стартует, порт занят | Порт держит вторая копия сервера или сторонняя программа | Закройте лишнюю копию. Диапазон `6117`-`6123` не используйте, он занят внутренними службами |
| Ассистент не видит проект | ProjectMaker закрыт или проект в нём не открыт | Запустите ProjectMaker, откройте проект и повторите запрос |
| Инструменты устройства возвращают ошибку | Устройство не запущено | Попросите ассистента сначала запустить устройство |
| Не скачивается архив с GitHub | Ограничения провайдера в вашем регионе | Попробуйте другое подключение. Если не выходит, напишите в поддержку, файл пришлют напрямую |

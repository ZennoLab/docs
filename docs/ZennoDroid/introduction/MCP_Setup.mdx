# ZennoDroid MCP: руководство по настройке для AI-ассистентов

<DisclaimerNotice />

:::warning Встроенные серверы недоступны внешним ассистентам
MCP-серверы, которые ProjectMaker ZennoDroid запускает сам (порты `6117`, `6118` и весь внутренний диапазон `6117`-`6123`), обслуживают только встроенный ИИ-чат. Внешний клиент получает ошибку `401`, а в лог продукта пишется `ingress refused`. Записи `ProjectMCP` (`6117`) и `AndroidMCP` (`6118`), добавленные в клиент раньше, больше не работают, их можно удалить.

Своего ассистента подключайте к собственной копии сервера, запущенной с вашим API-ключом. Она работает на портах публичных серверов рядом со встроенными серверами и не мешает чату:

- **projectmaker-droid** (управление проектом) → `http://localhost:6217`
- **android-pm** (инспекция Android-устройства) → `http://localhost:6211`

Как выпустить ключ и запустить серверы — ниже, в разделе «Подготовка».
:::

:::caution Порты ZennoDroid отличаются от ZennoPoster на +10
Это сделано специально: ZennoPoster и ZennoDroid часто установлены на одной машине и могут быть запущены одновременно. Поэтому общие порты AI-стека ZennoDroid сдвинуты на **+10** относительно портов ZennoPoster — конфликта не возникает, оба продукта можно держать открытыми и подключать к разным наборам MCP-серверов. Исключение — серверы устройств `MCP.Android`: они есть только в ZennoDroid и занимают `6211` и `6212`.

Если вы скопировали конфигурацию из [руководства по ZennoPoster MCP](/zennoposter/Hello/MCP_Setup) и указали `6207` / `6208`, ассистент будет подключаться к **ZennoPoster**, а не к ZennoDroid — для ZennoDroid нужны `6217` и `6211`.
:::

# Подготовка: ключ и свои серверы

Делается один раз. Требуется ZennoDroid 2.6.1 или новее. Нужны два сервера:

- **projectmaker-droid** (управление проектом) → `http://localhost:6217`
- **android-pm** (инспекция Android-устройства) → `http://localhost:6211`

## Шаг 1. Выпустите API-ключ

1. Запустите ProjectMaker ZennoDroid и откройте нужный проект.
2. Откройте **Settings → API Keys → Add**.
3. Задайте метку, уровень (tier) и права (scopes). Чтобы ассистент только читал проект и устройство, хватит уровня `T0` и прав по умолчанию. Чтобы он правил проект, добавьте права на запись и поднимите уровень.
4. Нажмите **Generate API Key** и сразу скопируйте ключ: второй раз его не покажут.

## Шаг 2. Скачайте серверы

На [странице релизов](https://github.com/ZennoLab/zennoposter-mcp/releases) скачайте последние версии двух архивов: `MCP.ProjectMaker-v…-win-x64.zip` и `MCP.Android-v…-win-x64.zip`. Распакуйте каждый в свою папку. Устанавливать .NET не нужно.

## Шаг 3. Запустите серверы со своим ключом

Откройте папку сервера, напишите в адресной строке проводника `powershell` и нажмите Enter. Подставьте свой ключ вместо `zp_xxx`.

```powershell title="Проект, порт 6217"
.\ZennoLab.AI.MCP.ProjectMaker.exe --urls http://localhost:6217 `
  --ProjectMaker:BaseUrl=http://localhost:5309/api/v1 --ProjectMaker:ApiKey=zp_xxx
```

```powershell title="Устройство, порт 6211"
.\ZennoLab.AI.MCP.Android.exe --Android:ApiKey=zp_xxx
```

Оба окна консоли держите открытыми, пока работаете с ассистентом. Чтобы не вводить ключ каждый раз, впишите его в поле `ApiKey` файла `appsettings.json` рядом с exe и запускайте сервер двойным кликом.

Для задач ZennoDroid (раннер) нужны серверы `6220` (задачи и сессии) и `6212` (устройства выполняющихся задач). Их команды и описание прав ключа — на странице [Публичный API и MCP-серверы](/zennoposter/Hello/public-api-mcp).

# 1. Чем ZennoDroid MCP отличается от ZennoPoster MCP

Отличий два, и второе принципиальнее первого.

| | ZennoPoster | ZennoDroid |
|---|---|---|
| Сервер проекта | **projectmaker** `6207` | **projectmaker-droid** `6217` |
| Второй сервер | **instance-pm** `6208` — управляет браузером | **android-pm** `6211` — читает состояние Android-устройства |
| Режим записи (recording) | используется — действия в браузере пишутся в кубики | **не используется** — в ZennoDroid нет действий, требующих записи |
| Управление UI из MCP | есть: клики, ввод текста, навигация | **нет**: только чтение состояния устройства |

**Главное отличие.** Сервер `instance-pm` в ZennoPoster умеет *действовать* — кликать, вводить текст, переходить по ссылкам. Сервер `android-pm` в ZennoDroid умеет только *смотреть*: получить XML-дерево экрана, разрешение экрана, список приложений, состояние устройства.

Все действия на устройстве в ZennoDroid — это **кубики проекта**. Ассистент добавляет их через сервер проекта (`projectmaker-droid`), а выполняются они при запуске проекта (F5). Поэтому «нажми кнопку в приложении» в ZennoDroid означает «добавь в проект кубик, который нажмёт эту кнопку», а не «нажми её сейчас».

Практическое следствие: элемент, которого нет на экране прямо сейчас, — не препятствие. Кубик собирается по имени/тексту/атрибуту элемента и срабатывает во время выполнения проекта.

> Точный список инструментов каждого сервера и их параметры ассистент получает от MCP-серверов сам, при подключении. Спросите его — он перечислит то, что доступно в вашей сборке.

# 2. GitHub Copilot

## Шаги

1. Убедитесь, что ProjectMaker ZennoDroid и ваши копии серверов запущены.
2. Откройте папку профиля пользователя: нажмите `Win + R`, введите `%USERPROFILE%`, нажмите Enter.
3. Создайте в этой папке файл `.mcp.json`
   (пример: `C:\Users\YourName\.mcp.json`)
4. Вставьте следующий код:

```json
{
  "servers": {
    "projectmaker-droid": {
      "type": "http",
      "url": "http://localhost:6217"
    },
    "android-pm": {
      "type": "http",
      "url": "http://localhost:6211"
    }
  }
}
```

5. Перезапустите Visual Studio (или перезагрузите расширение Copilot).
6. Теперь Copilot получит доступ к обоим MCP-серверам во всех рабочих пространствах.

:::tip Если вы работаете и с ZennoPoster, и с ZennoDroid
Можно держать в одном `.mcp.json` все четыре сервера — имена должны различаться, порты уже различаются:

```json
{
  "servers": {
    "projectmaker-droid": { "type": "http", "url": "http://localhost:6217" },
    "android-pm":         { "type": "http", "url": "http://localhost:6211" },
    "projectmaker":       { "type": "http", "url": "http://localhost:6207" },
    "instance-pm":        { "type": "http", "url": "http://localhost:6208" }
  }
}
```

Учтите: ассистент увидит инструменты обоих продуктов одновременно и может обратиться не к тому серверу. Если это мешает — уточняйте в запросе, о каком продукте идёт речь, или держите подключённым только нужный набор.
:::

# 3. Claude Code (CLI)

## Шаги

1. Убедитесь, что ProjectMaker ZennoDroid и ваши копии серверов запущены.
2. Откройте терминал.
3. Выполните следующие команды:

```sh
claude mcp add projectmaker-droid --transport http http://localhost:6217
claude mcp add android-pm --transport http http://localhost:6211
```

4. Проверьте, что серверы зарегистрированы:

```sh
claude mcp list
```

5. MCP-серверы теперь доступны глобально во всех сессиях Claude Code.

> Чтобы удалить их позже:
>
> `claude mcp remove projectmaker-droid`
>
> `claude mcp remove android-pm`

# Устранение неполадок (Troubleshooting)

## Ассистент подключился, но видит проект ZennoPoster, а не ZennoDroid

Самая частая ошибка при переходе с руководства по ZennoPoster: в конфигурации указаны порты `6207` / `6208`. Это публичные серверы ZennoPoster. Для ZennoDroid нужны **`6217` и `6211`**.

Проверить, кто на каком порту слушает:

```powershell
netstat -ano | findstr ":6207 :6208 :6211 :6212 :6217 :6220"
```

Сопоставить PID с процессом:

```powershell
Get-Process -Id <PID>
```

## Ассистент получает ошибку `401`

Клиент подключён к встроенному серверу (`6117`-`6123`): он обслуживает только встроенный ИИ-чат и не принимает внешних клиентов. Запустите свою копию сервера и укажите в клиенте её порт: `6217`, `6211`, `6212` или `6220`.

## Инструменты чтения устройства возвращают ошибку или пустой результат

- **Устройство не запущено.** Чтение экрана, списка приложений и разрешения требует поднятого устройства. Попросите ассистента сначала поднять устройство — соответствующий инструмент идемпотентный, лишнего не сделает.
- **Устройство не выбрано.** Для реального телефона он должен быть подключён и виден ZennoDroid (см. [подключение устройства](../Enterprise/Connection)).

## Команда `claude` или `codex` не распознаётся

Если при выполнении команд терминал выдаёт ошибку вида:

```
"claude" не является внутренней или внешней командой,
исполняемой программой или пакетным файлом.
```

или (в PowerShell):

```
claude : Имя "claude" не распознано как имя командлета, функции,
файла сценария или выполняемой программы.
```

(аналогично для `codex`), это означает, что папка с исполняемым файлом CLI **не добавлена в переменную окружения `PATH`**, либо CLI ещё не установлен, либо терминал не был перезапущен после установки.

> ⚠️ **Важно:** установщик Claude Code с сайта (native installer,
> `irm https://claude.ai/install.ps1 | iex`) **не добавляет** себя в `PATH`
> автоматически. Поэтому «установил с сайта, но команда не распознаётся» —
> это самая частая ситуация. Её решает Шаг 2 ниже.

### Шаг 1. Найдите, где установлен CLI

Расположение исполняемого файла зависит от способа установки.

**Claude Code:**

| Способ установки | Папка с `claude` |
|---|---|
| С сайта (native): `irm https://claude.ai/install.ps1 \| iex` | `%USERPROFILE%\.local\bin` (например `C:\Users\ВашеИмя\.local\bin`) |
| Через npm: `npm install -g @anthropic-ai/claude-code` | папка npm, обычно `%APPDATA%\npm` |

**OpenAI Codex CLI:**

| Способ установки | Папка с `codex` |
|---|---|
| С сайта: `irm https://chatgpt.com/codex/install.ps1 \| iex` | папка, указанная установщиком |
| Через npm: `npm install -g @openai/codex` | папка npm, обычно `%APPDATA%\npm` |
| Бинарник с [GitHub Releases](https://github.com/openai/codex/releases) | папка, куда вы распаковали `codex.exe` |

Точный путь npm-папки можно узнать командой:

```powershell
npm config get prefix
```

Проверить, видит ли система команду вообще (если пусто, её нет в `PATH`):

```powershell
where.exe claude
where.exe codex
```

Проверить, что файл существует (для установки Claude с сайта):

```powershell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
```

Если файла нет ни в одной из папок, значит CLI не установлен. Установите его одним из способов из таблицы выше (для npm нужен [Node.js](https://nodejs.org/)).

### Шаг 2. Добавьте найденную папку в переменную `PATH`

Подставьте путь из Шага 1 (например `%USERPROFILE%\.local\bin` для Claude с сайта
или `%APPDATA%\npm` для установки через npm).

**Вариант A: через графический интерфейс Windows**

1. Нажмите `Win + R`, введите `sysdm.cpl`, нажмите Enter.
2. Вкладка **«Дополнительно»** → кнопка **«Переменные среды»**.
3. В разделе **«Переменные среды пользователя»** выберите переменную `Path` → **«Изменить»**.
4. Нажмите **«Создать»** и вставьте нужный путь, например:
   `C:\Users\ВашеИмя\.local\bin`
5. Нажмите **OK** во всех окнах.

**Вариант B: через PowerShell (добавляет в пользовательский `PATH` навсегда)**

```powershell
# пример для установки Claude Code с сайта:
$p = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$p;$env:USERPROFILE\.local\bin", 'User')
```

> ⚠️ Замените путь на актуальный для вашего случая.
> Не запускайте команду несколько раз подряд, чтобы не дублировать записи в `PATH`.

### Шаг 3. Перезапустите терминал и проверьте

Изменения `PATH` действуют только в **новых** окнах терминала. Закройте и заново откройте PowerShell / CMD (или Visual Studio), затем проверьте:

```powershell
claude --version
codex --version
```

Для Claude Code также можно запустить встроенную диагностику (проверяет `PATH`, конфликты установок и т. д.):

```powershell
claude doctor
```

Если версии отображаются, значит команды распознаются корректно, и можно возвращаться к шагам настройки MCP выше.

### Частые причины, если не помогло

- **Терминал не перезапущен.** Изменения `PATH` применяются только в заново открытых окнах.
- **Несколько установок сразу** (npm + native) конфликтуют. Оставьте одну и удалите лишние.
- **Установлено только расширение для VS Code.** Оно не добавляет команду `claude` в терминал. Поставьте отдельный CLI с сайта или через npm.
